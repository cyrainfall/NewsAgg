# 沉淀循环：两条回路的机制、时机与信任标记

## Context

系统的复利承诺是"输出的内容会慢慢沉淀，为下一次输出做准备"（Q4）。此前已定下两个载体——认知资产（观点卡，ADR-0007）与风格资产（ADR-0008 把人的角色改为事后反馈）——但**回路的机制细节未定**，导致三个缺口：

1. **风格回路缺"原稿"这一端。** `wewrite learn-edits` 的签名是 `--draft {原稿} --final {终稿}`，其设计前提是"你在发布前改了 AI 初稿"。但无人值守取消了发布前审批（ADR-0008），你看到的是**已发布的成稿**。若基线取 `draft.md`，diff 会混入**审稿环节的 AI 改动**（AI 改 AI），从而把你从未做过的偏好当作你的偏好学进去。
2. **同一份 diff 会被重复学习。** `wewrite` 的规则是"同一范围重复至少两次且 `confidence >= 5` 才升为硬约束"。但如果你分三天改同一篇、系统每天 diff 一次，**同一次修改会被计三次**，凭空达到阈值——恰好击穿 wewrite 自己的保护机制。
3. **写回没有信任门槛。** 文章未经本人审核即已发布，而写回是自动的。一篇事后被认为写错了的文章，其判断已经进入认知资产；而认知资产是分拣层的**唯一读入**，一次错误判断会污染后续所有匹配。

## Decision

### 循环 A：认知（文章是载体）

```
分拣全量读卡 → 卡提供「当前判断 + 已覆盖事件」
   ↓ 写作时模型须引用或推进卡中判断（经 wewrite 的 brief/claims 承接）
发布成功
   ↓
写回：向**同一张卡**追加一条修订
     · 当前判断（可被推进，但不改写旧判断）
     · 依据事实（本次新增）
     · 修订史 += 一条
     · covered_events += 本次事件      ← 使下次能判「跳过 vs 续写」
     · 来源标记：哪篇文章、何时、发布状态、**未复核**
   ↓ 下次分拣读到更厚的卡 → 匹配更准、判断更深
```

**写回自动发生，但带未复核标记，且可被推翻。** 不阻塞写回（阻止写回等于放弃复利），而是让每次写回都留下可追溯的来源标记；当本人在后续反馈中提出异议时，系统将那条修订标为**已推翻**并追加一条更正记录。这样认知资产既能持续生长，又保留本人推翻它的痕迹。

### 循环 B：风格（本人的修改是载体）

```
风格访谈产出 style/style.yaml（种子，一次性）
   ↓ wewrite 按风格资产出稿
发布时写教学副本到 outputs/，并 commit（该 commit 即「发布快照」）
   ↓ 你修改它并 push
下次运行开始：git pull --rebase
   ↓
学习：diff（发布快照 ↔ 你的当前版本）→ wewrite learn-edits 提取 pattern
   ↓
同一 pattern 重复 ≥2 次且 confidence≥5 → 硬规则；否则只是软参考
   ↓ 旧规则按最后出现时间衰减，低于 2 停用
下次写作更接近你的文风
```

**基线 = 发布快照，不取 `draft.md`。** 这样 diff **只含本人的改动**，不混入审稿环节的 AI 改动。冷启动期间（Q45：系统先出稿、你在初稿上改）是**另一条独立路径**，那时基线才取 `draft.md`。

**发布快照不需要新机制——git 就是快照。** `outputs/` 已入仓且系统发布时会 commit，因此"发布时的确切内容"就是那次 commit 里的版本（`git show <publish_commit>:outputs/xxx.md`）。不需要另存副本或维护哈希基线；git blob 天然内容寻址。

> **修正（ADR-0036）**：这里少了一个前提——"发布那次 commit"必须被**记下来**。若靠 `git log -1 -- <path>` 事后推断，本人改稿 push 后取到的就是改稿而非发布快照，diff 恒为空、风格学习静默失效（实测踩到）。
> 现由 `publish.py` 在发布时把 `git_blob` 指纹写进发布账本。git 仍是存储，但**不再是索引**。

**按内容哈希去重，同一版本只学一次。** 记录"已学习到的版本"（教学副本的内容哈希），内容未变则跳过；变了才重新 diff。这直接补上缺口 2：一次修改无论被系统看到多少天，都只计一次。

**学习时机：挂在每日运行开头、`git pull --rebase` 之后。** 与 ADR-0018 的同步方式天然契合，无需额外调度。顺序上必须在**写作之前**（今天就能受益），且在 **pull 之后**（才能看到你的编辑）。

### 循环 C：表现（数据是载体，已有定义）

见 ADR-0010：表现数据只作为分拣的**排序参考**与简报内容，并驱动自动降频。它刻意保持"软"——每日一篇的样本量下，把噪音升成硬规则会适得其反。

### 一次运行的完整时序（两条回路的交汇点）

```
① git pull --rebase                       ← 取得你的编辑
② 风格学习（diff 发布快照 ↔ 当前，按哈希去重）  ← 必须早于写作
③ 采集 → 预筛 → 聚簇 → 读卡 → 三态决策
④ 写作（用最新的风格资产 + 更厚的卡）
⑤ 发布（四道门 + 反查验证）
⑥ 认知写回（追加未复核修订）
⑦ 写教学副本 + commit（该 commit 成为新的发布快照）
⑧ commit + push
⑨ 简报
```

② 早于 ④、⑥ 晚于 ⑤ 是这个时序的两个关键点：风格必须先学才能当天生效；认知必须在发布成功后才写回，否则会把未发出的判断写入资产。

## Consequences

- **两个回路的时间尺度不同，这影响可观察性**：认知回路每次发布都会前进（每天可见），而风格回路需要**重复出现**才升为硬规则（可能数周才见效）。因此短期内"风格没变化"是正常的，不应被误判为飞轮停摆。
- **风格回路只看得见本地编辑。** 若本人直接在平台上修改已发布文章（而非改本地教学副本），系统不会学习——因为比对的是仓内文件。这是已知局限，未消除；ADR-0017 已定系统不自动删改已发布内容，因此平台侧的修改只能靠本人同步回本地副本。
- **未复核标记使认知资产存在"待复核"状态**，而它可能长期无人处理（本人不读简报时）。这意味着分拣层读到的卡里可能混有未被本人认可的判断。这是无人值守的必然代价——与"人的接受度从事前审批降为事后反馈"是同一取舍的两面。
- **git 作为快照机制带来一个隐含依赖**：若 `outputs/` 的某个 commit 被改写（rebase、force push）或未成功推送，发布快照会丢失或错位。因此 `outputs/` 的历史应被视为**不可重写**，与认知资产同等级别。
- 哈希去重意味着**同一次编辑的"第二遍"不会被计入**，即使本人后来又改了同一处（内容变了则哈希变，会被重新学习）。因此"重复出现"的计数反映的是**不同的编辑事件**，而非同一次编辑被反复观察——这正是 wewrite 的阈值设计所预期的语义。
- 循环 C 的排序参考与循环 A 的写回都会影响下一次分拣，二者叠加时的相对权重未定；这属于待实测调优的范畴（与阈值同样处理，见 ADR-0016）。
