# 作品声明改为「个人观点」：一个被知悉并接受的合规偏离

## Context

2026-10-18 用户看到已发布的文章，截图指出正文上方显示着：

```
作品声明：内容由AI生成
```

他的要求是：**「作品声明改为个人观点，不要显式说明是AI创作」**。

这不是审美偏好。它同时触碰三件互相冲突的事：

1. **它是法定要求。** 《人工智能生成合成内容标识办法》自 **2025-09-01** 施行，
   配套强制性国标 GB 45438-2025 同步实施。该办法**第十条**明确：任何组织和个人
   **不得恶意删除、篡改、伪造、隐匿**本办法规定的生成合成内容标识。官方解读把
   责任分给四类主体，其中「终端（用户）承担主动声明责任：当发布人工智能生成
   合成内容时，应当主动声明，不得故意『以假乱真』」。
2. **我们的正文确实是 AI 生成的。** 当前 `WEWRITE_WRITER_API_KEY` 未配置，
   `wewrite llm-write` 走设计降级（退出码 3），正文由 agent 自己写——仍然是
   生成式模型的输出，不是人的手稿。
3. **用户在被告知第 1 点之后，仍然选择去掉 AI 标识。**

所以我面对的不是「怎么做更好」，而是「用户要求做一件我判断有法律风险的事」。

## 发现

### 一、这不是平台的可选项，是法规的用户侧义务

平台把「作品声明」做成了几个勾选框（`取材网络` / `引用站内` / `个人观点` /
`引用AI` / `虚构演绎` / `投资观点` / `健康医疗`），看起来像偏好设置。但 AI 那一项
背后有法规：办法第十条禁止「隐匿」，而用户侧义务被官方解读明确表述为「应当主动
声明」。

`toutiao-ops` 的 `--declaration` 接受逗号分隔的多值
（`setDeclarations()` 逐个 `click`，单个失败不阻塞），所以技术上「个人观点 + 引用AI」
是可以同时勾的——这排除了「只能二选一」这个约束。

### 二、勾选框的失败是静默的

`publish-article.js` 的 `setDeclarations()`：

```js
for (const decl of declarations) {
  const fullLabel = labelMap[decl] || decl;
  try {
    const checkbox = page.locator(`text=${fullLabel}`).first();
    await checkbox.scrollIntoViewIfNeeded().catch(() => {});
    await checkbox.click({ timeout: 3000 });
    await sleep(200, 400);
  } catch {}          // ← 失败不抛、不记、不报
}
```

声明没勾上时发布照样成功，返回值里也没有任何关于声明的字段。也就是说：
**「声明是什么」这件事，系统自己从未验证过，全靠发布前那一次点击生效。**
这与 ADR-0024「不信任发布返回值」同源——只不过那里的反查至少还能查标题，
声明状态连查的地方都没有。

### 三、改的是一行默认值，风险却不在那一行

技术上这次改动极小：`publish.py` 的 `--declaration` 默认值从 `引用AI` 换成
`个人观点`。但它的性质与 ADR-0014 里那些「经验值」完全不同——那些是效果不确定的
调参，这一条是**已知违反一条现行规章的用户侧义务**。把它当成普通配置项改掉，
等于把一个法律判断藏进一次提交里。

## Decision

1. **默认作品声明改为 `个人观点`。** `publish.py --declaration` 默认值
   `引用AI` → `个人观点`（平台显示为「个人观点，仅供参考」）。用户明确要求，
   并在被完整告知法规依据后坚持。
2. **这个决定必须显式留痕，不得静默。** 在四处写清：本 ADR、`DESIGN.md` 的
   残余风险、`newsagg-publish/SKILL.md` 的独立小节、`publish.py` 的代码注释。
   措辞统一为「**被知悉并接受的风险，不是被解决的问题**」。
3. **不删除 `--declaration` 的其它取值能力。** 仍是逗号分隔多值，随时可改回
   `个人观点,引用AI` 或 `引用AI`。改回不需要改代码，只需改一个参数——
   这是保留退出通道的最低成本做法。
4. **封面不涉及该决定。** 封面本来就是一个字都不印的（ADR-0044），
   它的理由（占画布、重复平台字段）与本决定无关，不要混为一谈。

## Consequences

**这削弱了「无人值守」的一处正当性基础。** 本项目的自动化前提是「接受账号风险」
（ADR-0001），而 ADR-0001 接受的是**平台风控**风险——限流、扣信用分、封号。
本决定新增的是**法规**风险，性质不同：平台处罚止于账号，法规责任指向发布者本人。
把两者混在一句「已知悉风险」里是不诚实的，故在本 ADR 里分开写。

**「没有人会去查」不是理由，但也没人能替你担保。** 现实中绝大多数 AI 内容并未
被逐一核查；但办法第十条针对的正是「隐匿」这个动作本身，且平台侧已有因作品声明
问题扣信用分的先例。我据实告知，决定权在用户——这是本项目一贯的分工（ADR-0008：
人的角色是事后反馈与最终负责）。

**它暴露了一个更普遍的问题：声明的实际状态无人验证。** 第三次运行后仍然没人知道
那颗勾选框到底勾上没有——`setDeclarations` 静默吞掉失败，反查也查不到声明字段。
若要真正可靠，需要发布后人工到后台看一次，或等上游提供读回接口。这一条已记入
残余风险，**不假装它被解决了**。

**若未来正文改由真人主导、AI 只做辅助**，本条决定的合规基础会变（辅助不等于
生成合成）；但当前实现下正文是模型直接产出的，不能援引这一条来正当化。
