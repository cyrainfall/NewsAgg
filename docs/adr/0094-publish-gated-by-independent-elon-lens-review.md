# 发布前加一次「独立评审」：换个模型，用马斯克视角挑毛病

## Context

2026-10-31 用户提出：发布前应该起子智能体、加载 `elon-musk-perspective` 技能评审成稿，
并且**诚实接收意见并做调整**。

这不是第一次有人指出「自查靠不住」，但这个提议和以往不同：以往的自查都是同一个模型、
同一份上下文里的自我复核，而本仓库已经连续四天出现「报告全绿、东西是错的」：

- ADR-0092：简报 ④ 段读的是台账摘要，到期线与退役线在生产里从未生效，退出码 0；
- ADR-0093：闸门拒绝被渲染成「运行失败，请重跑」，简报自己写了一个会导向重复发文的建议；
- 封面孤字行（2026-10-31）：`problems: [] warnings: []` 全绿，图在 320px 下是排版事故；
- 10-30 成稿：三处硬数字（市值蒸发、收盘价、涨跌幅）与一条核心判据都是错的，
  由**人**读出来才改掉。

四次的共同点：判断者与被执行者是同一个东西。所以缺的不是又一条规则，而是
**一个愿意反对的读者**。

## 决定

在「成稿写完」与「跑 `--after-write --publish`」之间插入一道评审关：

1. **评审由一个独立的子智能体做**（`subagent`，不共享主会话上下文，所以要显式给它文件路径）。
2. **它必须先加载 `elon-musk-perspective` 技能**，按该技能的心智模型与启发式评审，
   而不是给通用写作建议。选这个技能是因为它的提问方式天然反自查：
   第一性原理（你给的是机制还是现象）、白痴指数（有没有拆到成本/零件）、
   五步算法里的**质疑需求**与**删除**（哪一段删掉后读者的行动依据不变）。
3. **评审意见落盘**到 `docs/reviews/<日期>-elon-review.md`（入库、可回溯、次日可复核），
   格式是 `verdict / blockers / improvements / what_survives / musk_lens_notes`。
4. **主智能体必须逐条判 accept / reject**：accept 的真的改稿；reject 的写明理由
   （指证据或指规则，不接受「我觉得没必要」）。
5. **评审若一条 blocker 都没提**，必须在评审记录里明写「这是真没问题，还是评审被写成了夸奖」，
   不允许把沉默当成通过（ADR-0057 的同型：绿色可能是假阳性）。

## 为什么是「评审」而不是「重新写一遍」

要求子智能体**只判不改**：它输出的是意见，改稿仍由主智能体做。理由与 ADR-0025 一致——
技能装判断、脚本装确定性；这里推广成「评审装判断，写作装执行」。若让评审直接改写，
主智能体就无法对改动负责，也没法在记录里留下「我为什么改/不改」。

## 代价与边界

- **多一次模型调用**（评审子智能体读完成稿 + 技能文件，约一次完整写作的成本）。
  每天一篇的前提下可接受；它换来的是一次真正的外部视角。
- **不拦发**，拦发权仍归主智能体：评审是建议集合，主智能体可以 reject，
  但 reject 必须写理由。这与 ADR-0082（正文规则只打标签不拦发）同理——
  拦错一次损失一篇产能，而正确性由「记录 + 次日复核」保证。
- **评审也会错**：它可能没读懂、或把非共识当错误。所以 `what_survives` 是必填项——
  它强制评审先说清「哪里别改坏」，避免主智能体顺着意见把骨架改塌。
- **未做**：没有把评审分数写进发布账本（因此无法统计「评审提出的 blocker 里有多少被采纳」）。
  要做的话得先定义 blocker 的稳定标识，那是另一个决定。
