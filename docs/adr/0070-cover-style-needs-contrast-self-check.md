# 换材质换掉了参照系，自检的判据也必须跟着换

## Context

ADR-0067 引入「封面样式每日轮换」：8 种材质（`ink`/`paper`/`slate`/`cream`/
`cobalt`/`forest`/`mono`/`blush`）由日期哈希确定性选出，三种布局与样式正交。

改完之后我核查这套改动，发现一个**自检全过但产出物不合格**的缺陷。

**症状**：把 8 种样式逐个生成封面，统计像素，全部 `problems: []`
`warnings: []`——自检一声不响。但用 WCAG 公式量墨色与底色的对比度：

| 样式 | 颜色 | 对比度 | 判定 |
|---|---|---|---|
| `blush` | accent `(214,78,96)` 珊瑚 on `(240,232,228)` | **3.39** | 不达标 |
| `cream` | muted `(128,116,100)` on `(247,240,226)` | **4.03** | 不达标 |
| `blush` | muted `(124,112,110)` on `(240,232,228)` | **3.95** | 不达标 |
| `paper` | accent `(196,30,30)` on `(244,242,237)` | 5.29 | 达标 |
| 深色系 | ink / slate / cobalt / forest / mono | 5.70~18.77 | 达标 |

也就是说：`blush` 的 kicker 与 hero 单位（珊瑚色）在暖灰纸底上只有 3.39 的对比度，
低于 WCAG 正文级 4.5:1。文字画上去了，读者看不清。

**自检为什么没抓到**：`edge_check` 判「有没有侵入边距」，`safe_zone_check` 判
「有没有落进 3:2 裁切区」——两者判的都是**内容画在哪**，不判**内容看不看得见**。
`tests/test_make_cover_style.py` 钉的是「墨与底 sum-abs > 60」，那是「是墨不是底」的
判据，同样不涉及亮度差。**换了一种材质，自检的参照系换了，它却没跟着换判据。**

这是 ADR-0044 发现六（「自检会复述设计意图」）的同型：自检的判据是从上一套
设计里继承的，而设计换了。

**根因是一个颜色承担了两种角色。** `accent` 既是装饰条的颜色（9~11px 高的
色带，与底色贴在一起也无所谓），又是 kicker 与 hero 单位的小字颜色（缩略图下
必须读得出来）。这两种角色的对比度要求差一个数量级，而目录里只声明了一个
`accent`，两处用同一个值。

## Decision

### 一、补一条对比度自检

新增 `_rel_lum()` / `contrast_ratio()` / `contrast_check()`，查的是 `drawn` 里
记录的**实际画上去的颜色**，不是「这个元素按惯例该用哪个色」——这是 ADR-0044
发现六的教训：自检必须读产出物本身。

`drawn` 每项新增 `color` 字段，在绘制处记录画时用的颜色：kicker 与 unit 用
`accent`、hero 与 statement 与 line1 用 `ink`、payoff 与 line2 用 `alt`。
脚注（note）用 `muted` 但**不查**：它在卡片上只有 3.6px，本来就不可见，
硬拦会把浅色纸样式整个判死，而「脚注在信息流里不可见」是 ADR-0049 已经
确立的已知取舍。

### 二、字号按读者看到的尺寸判，不按画布尺寸判

封面在桌面信息流里只有 156px 宽（ADR-0049 实测）。画布上 42px 的 kicker 到
卡片上只剩 5.5px。WCAG 的大字门槛是 24px——按画布尺寸判它是「大字」（3:1
就放行），按读者看到的尺寸判它是正文（4.5:1）。

判据跟着读者看到的尺寸走，才和 ADR-0049 的整节推理一致：`contrast_check`
接一个 `scale` 参数，调用处传 `FEED_CARD_W / size[0]`。

这条选择是**回归钉住的**：同一个 42px 的 kicker，用旧色值时按画布尺寸判
放行、按卡片尺寸判报错——测试 `test_check_is_scale_aware` 钉住这个差异。
不钉住的话，下一个人很容易「简化」成按画布判，然后缺陷悄悄回来。

### 三、只改真正不达标的三个色值

`blush` accent `(214,78,96)` → `(179,65,80)`（3.39 → 4.58，保持色相压到 84%）；
`cream` muted `(128,116,100)` → `(119,107,93)`（4.03 → 4.58）；
`blush` muted `(124,112,110)` → `(114,103,101)`（3.95 → 4.52）。
其余五种样式一个值都没动。

### 四、⚠️ 我第一版的诊断数据是错的

第一版我用 `0.2126R + 0.7152G + 0.0722B` 算相对亮度——**漏了 sRGB 线性化**，
算出 `blush` accent 2.16、`cream` accent 2.89 这种值，并据此把 8 种样式的
材质全部压暗（`paper` muted 从 `(110,108,104)` 压到 `(70,68,64)`、
`blush` accent 压到 `(135,30,44)`……）。

用正确的 WCAG 公式（每通道先 `v/12.92 if v <= 0.03928 else ((v+0.055)/1.055)**2.4`）
重算后，真实值高得多，八种样式里只有三个不达标。**差一步线性化，代价是把
八种精心设计的材质全部破坏性地改暗。**

教训：**报出来的数字必须用与标准一致的定义算一遍**。错的判据比没有判据更贵——
没有判据你只是不做决定，错的判据让你做完一个破坏性的决定还觉得自己在把关。
这与 ADR-0044 的「看着怪不是判据，统计像素才是」同源：数字也必须有正确的口径。

## Consequences

- 8 种样式现在都能通过自检，且新增测试会逐个生成、逐个断言无对比度问题。
- **换材质不再是「换个参照系」的自由**：新增样式必须声明满足 4.5:1 的
  accent/muted/ink/alt，否则 `test_accent_and_muted_reach_450_against_bg`
  会拦住。目录从此有了可执行的准入门槛。
- 「装饰条与小字共用一个颜色」这个根因没有消除，只是把值压到两边都达标。
  真正干净的做法是给目录加一个独立的 `deco_accent`（可与文字色不同），
  但那要改 8 种样式的语义与 ADR-0067 的定义，超出本次范围。
- 脚注仍不查对比度。它在 156px 卡片上不可见是已知取舍；若将来把脚注放大
  或改成别的信息层，这条检查需要重新纳入它。
- 本次只覆盖了 `make_cover.py` 的文字元素。**照片层不影响判据**：
  有照片时 `layout_*` 仍然先画一整幅 `st["bg"]` 底的 panel，照片是贴在上方
  独立的一条带子里（`PHOTO_BAND=0.50`），文字全部画在 panel 里——所以
  「文字的底色」始终是 `st["bg"]`，参照系没有变。
