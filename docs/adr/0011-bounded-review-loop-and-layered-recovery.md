# 质检循环设上限，熔断恢复先探测后人工

## Context

两条无人值守下的失控路径需要兜底。

其一，`wewrite-review` 的契约是"未通过就直接改稿并复审，只有通过才生成成稿"——**这个循环没有上限**。在有人的场景下这没问题，因为人随时能叫停；在无人值守下，一篇反复审不过的稿会持续消耗预算直到撞上每日上限（ADR-0006），结果是烧掉当日预算且不产出，且从外部看这像一个成本问题而不是质量问题。

其二，熔断之后如何恢复没有定义。而这里有一个容易混淆的点：ADR-0001 规定"不做自动重试"，但那条规则的目的是**避免重复发文**（平台明令禁止批量发布重复内容），它针对的是**发布这个写操作**，不是针对只读的状态探测。

## Decision

**质检循环设上限**：最多复审 2–3 轮，仍不通过则当日弃权并告警，草稿与审稿报告一并存入简报（弃权本就是合法结果）。

**熔断恢复分两段**：先自动重试探测 3 次，仍失败则转人工（修复后手动解除熔断标记，下次调度自然恢复）。

**明确区分两类重试**：
- **只读探测可自动重试**（如登录态检查、发布前预检）。重试无副作用，能吸收网络抖动。
- **写操作不自动重试**（发布）。结果未知时须先回后台核实（见下），而非直接重发。

## Consequences

- 公布类写操作的结果未知时（点击发布后连接断开），必须先回后台内容列表核实该标题是否已存在，确认不存在才允许重试；核实不清一律熔断等人。**不做"超时即重发"**，因为那正是重复发文的成因。
- 熔断的自动探测只探测、不发布，因此不会在限流未解除时把内容推出去。
- 复审上限意味着系统会明确产出"今天弃权，原因是稿子审不过"这一状态。它必须与"今天没有选题"在简报中区分开——两者都是弃权，但需要完全不同的介入。
- 上限设为 2–3 轮是经验值，不是推导值；若实测发现审稿标准过严导致频繁弃权，应调整的是审稿标准而非单纯放宽轮数。
