# 首次真实发布：反查验证有效，但默认同发了微头条

## Context

按 ADR-0027 阶段 0，本人确认后执行首次真实发布（不可逆动作）。这是 `publish.py` 的反查验证（ADR-0024）与 `writeback.py` 的认知写回（ADR-0026）**第一次在真实数据上运行**。

## 结果

**发布成功**，且反查验证流程本身工作正常：

```json
{"ok": true, "mode": "publish",
 "steps": [{"step":"auth_check","attempt":1,"ok":true},
           {"step":"publish","mode":"publish","code":0}],
 "verify_code": 0,
 "verify_result": "title_found",
 "verdict": "title_found"}
```

**这验证了 ADR-0024 的核心设计**：不看 `toutiao-ops` 的返回字段，而是用 `content list` 反查标题。反查确实找到了标题——即"发布是否真的成功"这个问题，只有反查能回答，而它给了肯定答案。

### 但发现一个真实缺陷：默认同发了微头条

头条发布页有一个「同时发布微头条」的勾选框，**默认已勾选**；`toutiao-ops` 只在传入 `--no-weitoutiao` 时才取消它。本包装层**未传该参数**，因此本次发布了**两条内容**：

| 类型 | 标识 | 实测可达性 |
|---|---|---|
| 微头条 | `weitoutiao.zjurl.cn/ugc/share/thread/1879036395626759/` | HTTP 200 |
| 文章 | `www.toutiao.com/item/7696532785528160795/` | HTTP 301（正常跳转） |

两条都带同一标题（数据中可见 `assembleCell.itemCell.articleBase.title` 出现两次）。

**根因**：`publish-article.js:86-88` 的逻辑是"默认勾选，`opts.weitoutiao === false` 时才取消"，而包装层未传该选项。

**这是包装层的疏漏，不是上游缺陷**——上游的行为是显式的（参数名就叫 `--no-weitoutiao`），我们的调用漏了它。

### 反查验证的一个精度问题

反查只检查"标题是否出现在响应中"，因此**无法区分**"只发了文章"与"文章+微头条都发了"。本次两条同名，反查返回 `title_found`，判定为成功——结论正确（确实发出去了），但**精度不足以发现多发了内容**。

此外，`content list` 的返回结构极深（`items[0].data[0].assembleCell.itemCell.*`），而非 `items[*].data.msg_list[*]`（ADR-0032 记录的路径只对空列表成立）。这说明**反查不应依赖固定路径**，只能做"全文包含标题"这类弱匹配，或者需要按类型分别取数。

## Decision

**一、包装层必须显式传 `--no-weitoutiao`。** 本项目一次运行只应产出**一篇文章**（每日上限 1 篇，ADR-0014）。同发微头条会造成：内容重复（平台明令禁止"批量发布重复内容"）、无法用冷却期与每日上限约束、以及违反"产出物只有文章"这一模型定义（CONTEXT.md 已删除"平台稿"概念）。

**二、反查验证增加类型维度。** 除"标题是否存在"外，应记录查到的内容**类型与数量**，以便发现"多发了"。但鉴于返回结构复杂，此改进记为待办而非当前必做——当前的最小正确行为是"先确保只发一条"。

**三、本次超发的内容需人工处置。** ADR-0017 已定系统不自动删改已发布内容，因此这条微头条由本人决定删除或保留。

## Consequences

- **首次真实发布同时暴露了好消息与坏消息**：好消息是反查机制有效（ADR-0024 的设计得到验证）；坏消息是包装层漏了一个上游默认值，导致产出超出预期。这印证 ADR-0027"先撞墙"的价值——该缺陷在文档审阅时不容易发现，因为它是"默认值的语义"，而默认值不在参数表里。
- **平台侧的影响需要观察**：同一内容以文章与微头条两种形态同时发布，是否会被判定为重复内容，目前未知。这是本次实测带来的一个待观察项。
- **认知写回尚未执行**：尽管发布成功，但 `writeback.py` 未运行（本轮只验发布）。按 ADR-0026 的时序，写回应在发布成功后发生；留待修复 `--no-weitoutiao` 后的下一次发布一并验证，以免在缺陷状态下向认知资产写入数据。
- 反查验证的"弱匹配"性质被确认：它能可靠回答"发出去没有"，但不能回答"发了几条、什么类型"。后者需要更强的解析，而返回结构的复杂性使这一改进成本不低。
