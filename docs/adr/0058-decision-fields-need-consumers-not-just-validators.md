# 分拣的判断要被写作和简报读到，否则它等于没做

## Context

分拣层每天产出 `.newsagg/triage/<date>-decision.json`。这份决策里有几个字段不是给机器用的，是给**下游的人与模型**用的：`money_point`（这件事跟读者的钱或工作处境有什么关系）、`abstain_reason`（今天为什么弃权）、`ranking_note`（排序用了什么理由）。

ADR-0054 给决策 JSON 加了逐项字段校验，但只覆盖了 `low_confidence_skipped` 与 `no_card_available` 两个列表，并在 Consequences 里留了一条边界：

> 遗留边界：`abstain_reason` 与 `decision` 内部的 `money_point`、`ranking_note` 等字段同样被简报消费，但本轮只校验了这两个列表。

本次要把残余风险 40（钱落点写作纪律没有可执行检查）往前推一步，于是先按 ADR-0054 的指引去补校验。补之前先问了一个更基本的问题：**这些字段到底有没有消费方？** 结果发现那句话本身就是错的。

## 发现

### 一、`money_point` 没有任何消费者，一个都没有

对全仓做 `grep -rn money_point`，除 ADR-0054 那一行外零命中：`brief.py` 里 0 次、`build_brief.py` 里 0 次、`newsagg-triage/SKILL.md` 里 0 次。

而生产者一直在认真写。遍历 `.newsagg/triage/*-decision.json`：2026-10-12/14/17/18/19/20 六天完全没有这个字段，从 **2026-10-21 起每天都有**（与 ADR-0050 改赛道的日期吻合——模型自发开始写，因为 SKILL 的规则 9 提到了「钱落点」，但输出形状里没有它）。每天 300+ 字，具体到四类角色。2026-10-23 那天的开头：

> 四类角色各自的落点：① 接 AI 视频商单的个人与小工作室——报价 300 元/15 秒、成本能压到 100 元/15 秒以内…模型会员在涨（首充从 3999 涨到 4999）、积分在缩水（每月 15000 降到 6160）…

这是一次真正的判断：模型读了候选、选了事件、想清楚了「这事跟谁的钱有关」。**然后扔掉了。** 写作阶段看不到它，于是自己另猜一套角色划分；简报不印它，于是人也没机会复核。

这是本仓库第四次「记录了但没有消费者」：ADR-0038 的 `hot_history` 攒了三天的热度轨迹没人读、ADR-0042 的三份 frontmatter 解析器各写各的、ADR-0057 的 `tests/` 建好了没有任何东西会跑它。第四次说明这不是偶发，是**这个系统里字段只增不减、消费方靠记忆接**的结构性缺陷。

### 二、为什么 `grep` 会骗人：`### 钱落点` 含子串 `## 钱落点`

第一次审计「钱落点有没有进 brief」时，在 `.newsagg/briefs/*.md` 里 grep 到「钱落点」命中 2 次（10-21/22/23 每天 2 次），看起来「已经接上了」。逐字核对才发现两次都是 `build_brief.py` 里的**静态写作纪律段落**——一个固定的 `### 钱落点（2026-10-21 改赛道，ADR-0050）` 标题加三条通用要求（第 11/12/13 条），对每篇文章都一样。把 10-23 决策里 `money_point` 的前 40 字拿去在 brief 里找，结果是 `False`。

这个坑后来在测试里又踩了一次：断言 `assertNotIn("## 钱落点", text)` 永远为真（因为 `### 钱落点` 包含它），所以「字段缺失时整段省略」这条用例本来是假通过。改成断言完整标题 `## 钱落点（分拣已判定，写作必须落到这些角色上）` 才真的在测东西。

教训：**审计「某字段有没有被消费」时，用短串 grep 会被同名的静态文案骗过。** 判据要落在「这段内容是否逐字出现」，而不是「这个词是否出现过」。

### 三、缺失与空值在外部不可区分

如果只补校验不补消费方，会得到一种更糟的状态：模型被强制写 `money_point`，写作阶段仍然读不到它，而校验器报「通过」。于是「写了但没人读」变成了「写了、校验过了、还是没人读」——比不校验更难发现。

所以这次两件事必须同时做：**先接消费方，再补校验**。校验存在的理由不是「字段该有」，而是「下游读它的时候不能读到空」。

### 四、弃权理由是对外可区分的唯一依据

`abstain_reason` 同理。弃权是合法结果（SKILL 硬规则 5），但简报①段要写出「今天为什么不写」。缺了它，看守（ADR-0038）与人看到的是「今天没有文章」——而「今日无选题」和「系统根本没跑」在外部表现完全一样。ADR-0057 的 `Ran 0 tests / OK / exit 0` 是同一个形状：**静默的成功与静默的失败长得一样**。

## Decision

1. **`money_point` 接两个消费者。** 一是写作任务书：`build_brief.py` 在「## 真实素材锚点」之前插入 `## 钱落点（分拣已判定，写作必须落到这些角色上）`，正文明确写「这是分拣阶段做的判断，不是建议」「文章的钱落点必须与之一致」「若你认为它错了，不要静默改写，而是在正文里给出更准的角色划分并说明理由」。二是简报③段：`brief.py` 在「新在哪」之后印 `**钱落点（分拣判定）**：…`，**整段不截断**——它是散文，截断会把「具体到角色」压成空话。`money_point` 为空时两处都整段省略（历史决策没有这个字段，重放不能崩）。

2. **`continue` / `new` 必须有非空 `money_point`。** `triage.py --validate` 硬校验。理由：写作阶段拿不到它就会自己另猜一套角色划分，与分拣的判断不一致；而分拣是唯一读过候选池与观点卡的一步。`skip` 不要求——它不进写作阶段，没有落点可写，逼模型为它编一段只会产出假内容。

3. **`abstain` 必须有非空 `abstain_reason`。** 同上硬校验。理由见发现四：缺了它，「今日无选题」与「系统没跑」外部不可区分。

4. **只校验「该有内容时不能为空」，不校验内容质量。** 钱落点写得空泛（「对行业有影响」）或与文章实际内容对不上，机器看不出来——那是残余风险 40 的同一类东西。所以校验通过**不等于**写对了，别把它当质量门。这一条写进 SKILL，是因为最容易发生的误用就是把「校验过了」当成「写好了」。

5. **`ranking_note` 不补校验。** 它是排序过程的说明，不是下游输入（简报不读它，写作也不读它）。ADR-0054 把它和 `money_point` 并列是错的；它的正确位置是「只被人事后复核用」，而不是「必须存在」。真要管它，该管的是「排序理由与 `trend_summary` 是否自相矛盾」，那是另一件事。

6. **不升级为 `decision.schema.json`。** ADR-0054 说过「再出现一次同类丢失就升级」。本次确实又出现了一次，但结论是**不升级**：这次的缺陷不是「schema 覆盖不全」，而是「schema 里的字段没有消费者」。一份完整的 schema 会让 `money_point` 更严格地存在，但仍然不会让它被读到。补消费方才是修复；schema 是另一个问题（字段名契约漂移），留待它真的再发生时处理。

## 验证方式

- `python3 -m unittest discover -s tests` → **47 个用例**（原 32 + 本 ADR 新增 15）。新增 `tests/test_decision_payloads.py` 四个测试类：`MoneyPointIsValidatedTest`（5）、`AbstainReasonIsValidatedTest`（4）、`MoneyPointReachesWriterBriefTest`（3）、`MoneyPointReachesReportBriefTest`（3）。两个解释器（3.9.6 / 3.12.14）均通过；CI 在每次 push 跑（ADR-0057）。
- 每个消费者都有**正反两侧**用例：字段在时必须逐字出现、字段缺时整段必须省略。只有正向用例会漏掉「省略逻辑写错、历史决策重放崩掉」。
- 历史决策回归：`--validate` 对 2026-10-21 通过（有 `money_point`）、10-22/10-23 只报冷却期问题、**10-14/10-17/10-20 正确报缺 `money_point`**（这三天的决策早于 2026-10-21，本来就该报）、10-12（abstain 日）通过。
- 端到端：`build_brief.py --decision .newsagg/triage/2026-10-23-decision.json` 生成的 5977 字任务书含钱落点整段；`brief.py --date 2026-10-23 --stdout` ③段含 `**钱落点（分拣判定）**：四类角色各自的落点…`，五段与 ①②③④⑤ 齐备（看守判据未破坏）。
- **测试抓到的一个假通过**：`test_writer_brief_omits_section_when_money_point_absent` 最初用 `assertNotIn("## 钱落点", text)`，恒为真——因为静态纪律段落的 `### 钱落点` 含该子串（发现二）。改成断言完整标题后才真的在测。这条记在这里，因为它是「测试写了但没测到东西」的活样本，与 ADR-0057 的 `Ran 0 tests / OK` 同型。

## Consequences

- **字段有消费者之后，它的写法就有约束了。** `money_point` 现在会被整段塞进写作任务书并在简报里公开，所以写得含糊会立刻在成文里显形。这比「写得含糊没人看见」好，但也意味着分拣阶段的输出质量开始直接影响成稿质量——分拣不再是一个可以糊弄的中间步骤。
- **写作阶段多了一个必须遵守的约束，多了一处可能与分拣冲突的地方。** brief 里写了「若你认为它错了，在正文里说明理由」，这是刻意的：让冲突显形而不是静默改写。代价是成文里可能出现「分拣说 A，文章说 B」的段落，需要人读简报时留意。
- **简报③段变长了。** `money_point` 是 300+ 字散文且不截断，简报会明显变长。这是刻意的取舍：截断省下的几行，代价是「具体到角色」被压成空话，而那正是这一段存在的理由。
- **「记录了但没有消费者」的第五例仍可能出现。** 本次修的是 `money_point` 与 `abstain_reason`。`ranking_note` 被明确判定为不需要（Decision 5），但 `.newsagg/` 里还有别的只写不读的字段（如 `dropped` 的多数子字段、`source_meta.observations`）。判据应该固化成一句话：**加字段时同时指明消费方，否则别加**。
- **校验让分拣更容易在第 2 阶段停下。** 缺 `money_point` 会让 `run_all.sh` 的 `--validate` 报错并中断。这是有意的硬门，但代价是：若某天模型确实想不出任何角色落点（比如纯政策新闻），它现在必须弃权或跳过，而不能「写了文章但落点含糊」。这与 SKILL 规则 9 的「不要把它变成硬规则」有张力——规则 9 说的是**排序偏好**，本 ADR 说的是**字段必须存在**，两者不冲突，但读的人容易混。缓解是 SKILL 里两处都写了「无钱落点即弃权会让系统在只有纯技术新闻的日子系统性弃权」这句警告。
