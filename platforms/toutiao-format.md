# 头条推荐流的格式事实（2026-10-31 实测）

这份文件只记**观测到的事实**与**复测方法**，不记判断。判断在
`docs/reviews/2026-10-31-toutiao-format-review.md`，写作约束在 `prose-rules.md`
与 `title-rules.md`。

## 为什么要有这份文件

`title-rules.md` 里每条观察项都标着「待检验的假设」，`prose-rules.md` 同理。
检验需要平台样本，而样本此前从未落成文件——2026-10-28 那次复盘是人工读 13 篇、
人工数出来的，下次复盘又得从头来。这份文件把「平台长什么样」固定成一个可以
逐次对照的基线，并且写明它是**哪一天、多少样本**量出来的。

## 样本与方法

- **热榜话题**：50 条，取自本地 DailyHotApi 的 `/toutiao`（与采集层同一个源），
  2026-10-31 00:50 快照。
- **正文样本**：7 篇，`m.toutiao.com/i<id>/` 移动页服务端渲染的 `<article>`。
  取法：站内搜索命中 → 手工挑与本赛道读者相近的（AI/程序员/工资/副业/职业）。
- **封面样本**：热榜前 10 条的 960×540 缩略图，逐张看过。
- **我们的成稿**：`outputs/*.md` 全 15 篇，同一把尺子。
- 工具：`scripts/style_probe.py`（stdlib，无依赖），存档到
  `.newsagg/platform-samples/<日期>.json`。

**样本局限，先说清楚**：n=7，来自搜索结果而非随机抽样，而且**看不到这些文章的
阅读量**——所以下文只能说「平台上长这样」，**不能说「这样才会爆」**。前者是观测，
后者需要曝光数据，本系统拿不到。任何人拿这份文件论证因果，都是越界。

## 标题

| | 热榜话题（n=50） | 文章标题（n=7） | 我们（n=15） |
| --- | --- | --- | --- |
| 字数区间 | 8–20 | 17–53 | 18–30 |
| 中位数 | 15 | 31 | 27 |
| 问号 | 0 | — | 0 |
| 感叹号 | 0 | — | 0 |
| 含数字 | 15/50（30%） | — | 多数 |

- **热榜话题名和文章标题是两种东西**：话题名短（中位 15）、是「事件名」；
  文章标题长（中位 31）、是「作者的判断」。拿话题名的长度去砍文章标题是错的
  ——2026-10-31 我第一版判断就是这么错的（详见复盘）。
- 常见句式：`人名/媒体 + 冒号 + 判断`（邵永灵：乌克兰低头了 / 人民日报：警惕"中国AI跑偏论"），
  7 篇正文样本里有 3 篇是这个形状；`数字 + 反差`（53岁阿姨坚持15.8年 血脂实现逆转）；
  问句**不写问号**（第一个15万亿经济大省要来了吗）。
- 我们 27 字落在平台 17–53 的区间内，**标题长度不是问题**。这是本次测量推翻的第一个直觉。

## 封面

热榜前 10 条封面逐张看过，四种类型：

1. **人物海报**：作者本人职业照 + 超大姓名（书法/衬线体）+ 头衔（「头条精选作者｜经济学家」），
   深色城市背景，右下角带 `头条 @账号` 水印。适用于**读者认人不认题**的成熟作者。
2. **视频帧 + 立体大字**：现场/戏剧性照片（浓烟、人物抠图）上压 3D 描边字，
   字本身就是标题的情绪版（「胳膊拗不过大腿 / 乌克兰低头了」），16:9，带彩色边框。
3. **纯实景照片，零文字**：城市天际线、风光、现场照。字全交给标题，封面只负责"好看"。
4. **竖版视频截帧**：3:4（405×540），叠 2–3 层字幕 + 一个数字（「中国55%Token 消耗」）。

**我们的封面是第五种**：1200×675 纯文字模板（底色 + 一个巨大数字 + kicker + payoff）。
它不是错——它承载了「一个视觉论据」（ADR-0044），缩到 320px 仍可读。但它与平台热图的
共同点只有「16:9」：平台热图几乎都带**真人或实景**，我们的只有排版。

这件事目前**无法判定好坏**：我们拿不到「同标题不同封面」的对照数据。记在这里，
等有了 A/B 的条件再说，不要凭感觉改成"放个人物照"。

| --- | --- | --- | --- |
| 正文字数 | 1504 | 2343 | 我们 **+839** |
| 段数 | 26 | 20 | 我们 −6 |
| 段均字数 | 95 | 101 | 基本持平 |
| 最长段 | 151 | 183 | 基本持平 |
| 首段字数 | 38 | 97 | 我们 **+59** |
| 小标题 | 0（7 篇里 6 篇为 0） | 5 | 我们 **+5** |
| 内文图 | 2 | 0 | 我们 **−2** |
| 数字字符/百字 | 4.7 | 4.6 | 持平 |
| 引号/千字 | 7.1 | 7.7 | 持平 |
| 「我」/千字 | 0.7 | 2.4 | 我们更"我" |

稳定成立的四条（两次不同 n 都一致）：

1. **我们篇幅偏长**：+839 字（n=3 时只看到 +218，样本一扩差距就显出来了）。
2. **我们小标题过多**：平台 7 篇里 6 篇**一个都没有**。
3. **我们首段过长**：97 字 vs 38 字。
4. **我们没有内文图**：0 vs 2 张。

不成立的（第一版 n=3 时以为成立，n=7 后推翻）：

- ~~标题太长~~ → 我们 27，平台 31。
- ~~段落太碎/最长段太短~~ → 段均 101 vs 95，最长段 183 vs 151，都在同一量级。

## 已知缺口：正文插图

平台正文中位 2 张图，我们 0 张。这不是写作规则能解决的：发布链路里
`fetch_photo.py` 只服务于**封面**（Wikimedia 取图），vendor 的 toutiao-ops
没有正文插图接口。要做需要两件新东西：选图（相关性 + 版权）与编辑器上传。
在具备之前，写作要求里禁止写「如图」「见下图」这类空指。

## 怎么复测

```bash
# 1) 取平台正文样本（id 从站内搜索/转载页拿，头条搜索接口要签名，本项目不伪造）
.uv-tools/wewrite/Scripts/python.exe scripts/style_probe.py \
    --ids 7702342639261205021,7697408937204744758,7684174511343796772 \
          --ours

# 2) 只看我们自己（不联网）
.uv-tools/wewrite/Scripts/python.exe scripts/style_probe.py --ours
```

每次运行都会写 `.newsagg/platform-samples/<日期>.json`（含本次用了哪几个 id），
所以「这个结论是哪天的、多少样本」永远可复查。**样本换了，结论可能变**——
本次就变了一次，见复盘。
