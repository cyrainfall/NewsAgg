# 封面承载一个视觉论据，不复述标题

## Context

第一篇文章发布后，用户对封面的反馈是一句话：**「cover 不够吸引人」**。

这不是「难看」的抱怨，而是一个可以量化的判断。头条是推荐流：读者在信息流里
看到的是一张 320px 宽的缩略图，**标题就印在封面旁边**。所以封面与标题是同一个
位置上的两个元素，它们必然被放在一起比较。

旧版 `make_cover.py` 的做法是把标题排进画布：按字符数分档选字号（`≤12→h*0.16`、
`≤20→h*0.125`、`≤30→h*0.10`，否则 `h*0.08`），**写死分档、不做任何测量**，
加一条左侧竖条和固定标签「AI·开发者工具」。

量化诊断：把旧封面缩到信息流宽度 320px 后统计亮度，**亮像素（>120）仅占 4.7%**，
即约 95% 的画面是空暗区；正文在 320px 宽下只剩约 **8px 高**，读不出来。

于是旧封面两头的坏处都占了：**不增加信息**（复述标题），**还读不出来**（字号被
压到缩略图下不可辨）。

## 发现

### 一、封面必须承载标题没有说的东西

信息流里封面和标题并排出现。一句「Gemini 4 打五折：做应用的人在省钱，做模型的人
在挨打」印在封面上，读者并不会因此多知道任何事——他本来就要读标题。封面唯一的
价值是**在读者读标题之前或同时，给出一个可被一眼抓住的论据**。

所以封面要回答的不是「这篇文章讲什么」，而是「**这篇文章里最值得被记住的那个
事实是什么**」。它通常是：一个数字、两个相撞的短句、或一句断言。

### 二、写死字号必然溢出，测量才是不变量

原型阶段我做了三组变体，其中一组把一句 8 个字的短句按写死的 190px 字号绘制，
结果**直接溢出画布**。这条教训决定了整个实现方案：

> 所有文字的字号必须由**测量**决定，绝不写死尺寸再赌它放得下。

写死尺寸的后果比难看更严重——它会溢出画布，而**无人值守时没有第二双眼睛**。
一张溢出画布的封面会被发出去，没人看见。

### 三、三个只有靠统计像素才能发现的缺陷

实现过程中自检发现三处真实缺陷，都不是靠看缩略图能察觉的：

1. **单位交替匹配顺序错**。`NUM_RE` 写成 `(亿|万|千|倍)`，正则交替分支取首个能
   匹配的，于是「4 万亿元」被切成 `hero=4` / `unit=万`，丢掉了「万亿」的量级。
   修法：**长的单位排在前**（`万亿|美元|亿|万|千|倍|%|元`）。
2. **kicker 无截断**。`fit_font` 缩到 `MIN_MUTED=30` 的下限后就不再缩，长 kicker
   照样溢出。修法：缩到下限仍放不下时按宽度截断并加省略号。
3. **RGB 颜色被当成颜色列表**。`draw_lines_center` 用
   `isinstance(fills, (list, tuple))` 区分「单色 / 逐行颜色」，而 RGB 颜色本身
   就是 tuple —— `(247, 249, 253)` 被当成三个颜色，`fills[0]` 取到标量 `247`，
   PIL 把它读成 `(247, 0, 0)` 深红。**statement 布局的正文整片变红**，而缩略图上
   看着「只是有点怪」，直到统计像素颜色才暴露。修法：用 `_is_color()` 判断
   「长度为 3 且元素都是 int」。

第 3 条尤其说明问题：**「看着怪」不是判据，「统计像素」才是**。这与 ADR-0037
从 `analytics` 的 DOM 噪声里按白名单提取指标是同一条原则——上游返回的形状不能
假设，必须验证。

### 四、封面论据应该由写作阶段给出，不是从标题猜

`derive_parts()` 从标题里找数字与冒号来推导布局，它能保证「不出错」，但保证不了
「选对了论据」。真正的视觉论据来自**这篇文章的论点**，而那是写作阶段才知道的。

所以 `make_cover.py` 增加 `--spec <json>`：写作阶段把
`{"layout","kicker","hero","hero_unit","payoff"}` 写进 `.newsagg/covers/<日期>.json`，
封面阶段读它。优先级是**命令行 > spec > 标题推导**，后者作为兜底保留。

## Decision

1. **封面只承载一个元素**，三种布局：`number`（数字占满画面）、`contrast`（两个
   短句相撞）、`statement`（一句断言）。不再把标题排一遍。
2. **字号一律测量后自适应**（`fit_font` / `fit_block`），并在缩到下限仍放不下时
   截断。绝不写死尺寸。
3. **数字拆成 `hero` + `hero_unit`**：`hero` 放大到占满画面（`8160`），`hero_unit`
   缩到约三分之一（`亿参数`）。塞进同一字符串会把主字号压小。
4. **溢出必须被挡住，而不是被忍受**。`make_cover.py` 用像素检查内容是否侵入左右
   边距带（`edge_check`），溢出时 `problems` 非空且**退出码 1**，编排器据此不发布。
   判据必须是「像素侵入边距带」而不是「逐个文字测量」——后者要求每个绘制点都
   记得维持不变量，漏一处就静默溢出；前者与实现方式无关。
5. **装饰条不算侵入**。横跨全宽的顶/底蓝线天然穿过边距带，判据是「该行几乎只有
   一种颜色」则跳过——不靠调用方传参记得排除，否则漏传就误报，而**误报的自检
   等同于没有自检**。
6. **`--spec` 让写作阶段指定视觉论据**，标题推导降为兜底。优先级：命令行 > spec > 推导。
7. **`--spec` 文件缺失/非 JSON/非对象时显式报错退出 1**，不静默回退到推导——静默
   回退会让「我明明指定了论据」变成一句无人验证的假设。
8. **封面上不印 AI 标识。** 用户要求「cover 中不要出现 AI 辅助创作」。这条不是
   审美偏好：AI 标识由平台的**作品声明**承担（`publish.py --declaration 引用AI`），
   那是平台自己展示、可被检索的字段，在图上再印一行字是重复的；而且它要占掉
   7.5% 的画布高度，把垂直空间从论据那里抢走——封面上每一寸都该留给论据。
   `--note` 改为默认空。**这不改变合规**：作品声明仍在，AI 标识仍存在，只是
   不再重复画在图片像素里。
9. **kicker 有长度上限 16 字，超出就截断并给出 `warnings`**。这是第四条发现的延伸：
   kicker 是标签不是句子。长 kicker 不会溢出（`fit_font` 会缩到 30px 下限再截断），
   所以**溢出检查放行它**——但 30px 在 320px 缩略图下只有 8px 高，技术上「放得下」，
   实际上读不出。这正是「不变量要通过的检查」与「实际可读」之间的缝：
   自检只保证不溢出，保证不了「缩到不可辨」这种通过式的失败。

## Consequences

- **封面从「标题的排版」变成「论据的选择」**。这提高了对写作阶段的要求：写稿时
  要同时判断「这篇文章最值得被记住的事实是什么」。这个判断不能脚本化（与 ADR-0041
  「建卡由模型完成」同类），所以只把**产物**做成结构校验（`--spec` 的 schema 与
  溢出检查），判断质量仍由人看简报时抽查。
- **`edge_check` 是启发式，不是证明**。它检查「内容是否侵入边距带」，能抓住溢出
  与贴边，抓不住「字够小但排得难看」。它是**下限保护**，不是质量保证。kicker 的
  长度上限就是这条缝的实例：它**通过了溢出检查**，却缩到缩略图下不可读。
  这类「通过式失败」（check passes but the result is useless）是自检机制固有的盲区——
  自检能验证它被写成什么，验证不了它看起来怎样。所以封面仍需人眼看一眼。
- **两个 Python 解释器的不对称**：`make_cover.py` 依赖 Pillow，必须用
  `.uv-tools/wewrite/bin/python` 跑（ADR-0039 已记此坑）。`--spec` 的 JSON 解析
  也因此在这个解释器内完成，不引入新依赖。
- **`number` 布局的数字必须在标题里真实存在**。若 spec 指定了一个标题里没有的数字，
  封面与正文会对不上——这是**有意不做校验**的：论据可以来自正文而非标题，脚本
  无从判断哪个合法。
- **封面仍然不用新闻原图**（ADR-0013 的版权边界），也不引入图片生成模型
  （无 provider key，Q43/B）。所有封面都是纯 PIL 绘制的模板拼图。
- 实测对比（同一篇文章、信息流 320px 尺寸）：亮像素占比 **4.7% → 9.0%**、
  亮度标准差 **37.2 → 59.9**；主元素在 320px 宽下约 14px 高，可读。
- 这个改动**不改变发布链路**：`run_all.sh` 只是多传一个可选的 `--spec`，没有 spec
  时行为与之前一致（回退到标题推导）。
