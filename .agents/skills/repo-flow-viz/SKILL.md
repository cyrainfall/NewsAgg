# 仓库工作过程可视化

产出**一个** `.html` 文件：左栏流程节点，中栏该节点的动机与读写，右栏点开文件的**真实原文**。
读者全程不用碰文件系统。

## 三件事，一件不能少

1. **骨架**是流程节点，不是文件树。节点回答"这一步做了什么、为什么这么做"。
2. **每个节点挂着它真正读写的文件**，不是"相关文件"。
3. **点开文件看到的是磁盘上那几行的原文**，带真实行号。不是摘要，不是复述。

少了第 3 条，页面就退化成一张漂亮的目录图 —— 而"目录图"读者自己 `ls` 也能得到。

## 三层，别混

| 层 | 文件 | 认不认得仓库 |
|---|---|---|
| 事实层 | `scripts/lib_facts.py` | 认。所有路径、行号、锚点写在这里 |
| 渲染层 | `scripts/render_html.py` | **完全不认**。换仓库不用改一行 |
| 校验层 | `scripts/verify_facts.py` | 只读 facts + 只磁盘，重新对齐一遍 |

流程：`build_facts.py`（你写）→ `repo-facts.json` → `verify_facts.py` → `render_html.py` → `index.html`

**facts JSON 是唯一契约。** renderer 里出现任何具体路径都是设计失误。

`meta` 里必须有 `title`（页面标题）/`root`（verify 的 --root 默认值）/`source_script`（来源行）/`stats`（顶部统计条）。
`groups` 决定左栏分组与键盘顺序。**没有组的节点不会渲染，且是静默丢失** ——
改完 facts 看一眼页面节点数对不对。

## 做之前先想清楚的两件事

**读者是谁。** 一次只服务一个读者：接手的人要"从哪开始跑"，你自己半年后要"当时为什么这么定"。
服务不了两个。定不下来就按"接手的人"做 —— 他不会自己补上下文。

**颗粒度按"能独立解释"切。** 判据：这一步能不能用一句话说清"它做了什么、为什么"。
说不清就是切粗了。同一个函数被三步共用，就出现三次 —— 一节点一文件那种一一对应，
做出来的图是文件树的马甲。

节点数落在 10–20。少于 10 太粗，读者还是得去翻代码；多于 20 左栏就变成需要滚动的目录。

## 写 build_facts.py

```python
import sys; sys.path.insert(0, '<skill>/scripts')
import lib_facts as F
F.set_root('/abs/path/to/repo')
```

摘录工具（全部在 `lib_facts.py`，失败一律 `die()` 退出非零）：

- `ex(path, start, end)` —— 真实行号切片，最常用也最可信
- `at(path, anchor, before, after)` —— 字面子串定位，**优先于行号**：文件改了它跟着走
- `fn(path, defline, take=18)` —— 从签名切一段。`take` 宁小勿大
- `jsonview(path, keys)` / `jsonline(path, index)` —— 结构化视图，`start=None` 会在页面上标明
- `count_dir(glob)` —— 顶部统计条用。**必须磁盘数出来**，不写手写常数

**统计值不许手写。** 手写的 `["ADR", 65]` 三个月后是错的，而页面上不会有任何痕迹提示它过期。

## 校验：不通过就不要交付

```bash
python3 scripts/verify_facts.py facts.json
```

它跟生成过程**零共享代码**，从零重新对齐：每段摘录首行末行与磁盘逐字比对、`total` 是否还等于实际行数、
非线性摘录有没有交代清楚、引用到的文件是不是全图都点不到内容。

`exit != 0` 就是页面在撒谎。修 facts，不要改校验器放松标准。

## 诚实规则（这套东西的命根子）

页面上的每一个字都必须能追溯到磁盘。

- 摘录就是原文，**逐字**。想改写就放到 `note` 字段，别混进 `text`。
- `start/end` 只在确实是原文切片时才填。`jsonline` 的文本是 `json.dumps(indent=2)` 出来的，
  已经不是文件里那一行的样子 —— 标行号就是撒谎，用 `loc` 字段（"第 N 行 / 共 M 行（JSON 已格式化）"）说明。
- 折叠掉的细节要在 `note` 里交代丢了什么。161 元素的列表全量展开会淹没真正要看的字段，
  但**必须写明**"candidates 已折叠为 …(161 项)"。
- `does` / `why` 里出现数字、路径、函数名，必须来自读过的原文，不是凭印象。

**`why` 是整页最贵的字段。** "做了什么"读代码能看出来；"为什么"看不出来。
写不出来说明你还没读懂这一步 —— 回去读，不要拿"保证一致性"这类空话填坑。

## 已知坑

- `timezone(8)` → `TypeError`。要 `timezone(timedelta(hours=8))`。
- 锚点 miss 就 `die()`，别猜。锚点必须是行内**稳定**的字面文本。
- 摘录首行是空行 = 行号差一格，往上/下挪。
- renderer 的 JS 里 `const hay = n => ...` 被 `nodeEl()` 先调用会 TDZ 报错 → 用 `function hay(n)` 声明。
- 浏览器验证：改完文件必须 `ego_navigate` + `location.reload()`，只复用 file:// URL 会拿到缓存页。
- 校验器报错但页面看着正常 → 信校验器。它比肉眼可靠。
- **同一个仓库在会话期间被别的进程改动过**：校验器会在你以为"刚验证过"之后报 FAIL。
  这不是误报，是它该干的活 —— 修完重跑 build 就好，不要回头放宽标准。

## 交付

产出单文件 HTML（payload 在 `<script id="payload" type="application/json">` 里，无外部依赖）。
用 `present` 交出去，然后告诉用户：左栏选节点、点文件卡片看原文、`/` 搜索、`←/→` 翻节点。
