# 台账接上了，但接的是摘要：简报的到期线与退役线在生产里从没印过

## Context

2026-10-31 说要补「卡库退役机制」。打开 `brief.py` 才发现它**早就接上了**：
`_card_stock_lines()` 会调 `card_backlog.retire_candidates()`、会印「退役候选」与
「到期未建卡」。用 `2026-11-20` 模拟，它也确实能算出
`ai-tool-benefits-overestimated-by-demo-effect.md` 已 37 天未成文。

所以这一轮要修的不是「没有机制」，是「机制在生产里不响」。

## 发现

`brief.py` 的 ④ 段按 `backlog["issues"]` 逐条判「到期未建卡」，而它拿到的
`backlog` 是**分拣输入包里的那个字段**——那是一份**摘要**：

```json
{"threshold": 2, "review_days": 30,
 "due": [...], "open_issues": [...], "note": "..."}
```

**没有 `issues`**，连 `path` 都没有。于是：

- 生产：`issues` 读不到 → `due` 恒空 → 「到期未建卡」与
  「台账：N 个议题在跟」**从来没印过**；
- 测试：`tests/test_brief_card_backlog.py` 的用例手造了带 `issues` 的 dict
  → 全绿。

同一个字段还被 ② 段用（`_backlog_echo` 给候选条目回「第 N 次出现」），
同样空转。

这是本仓库第 N 次同形状的失败：**判据接上了、但接错了字段**（ADR-0042 的三份
frontmatter、ADR-0057 的假绿、ADR-0081 的空闸、ADR-0090 的 ACL 闸）。
它们共同的可检测特征只有一条：**测试夹具比生产输入**多**给了字段**。

## 决定

1. **修在消费方**：新增 `_load_backlog_full()`，摘要缺 `issues` 时按默认台账路径
   （`<root>/.newsagg/triage/card-backlog.json`；摘要给了 `path` 就用它）读回完整台账。
   不给输入包加字段——那会让包变胖，而且下一次改台账结构还是得同步两处。
2. **`backlog is None` 时不读**：那是「没有台账」（老日期重放），凭空读当天的
   台账去印「无到期」等于编。
3. **两条线都空时留一行「查过了」**：`_card_stock_lines` 的 docstring 早就写着
   「没有就印『无』——一行『无』比整段消失更有用」，而实现是静默的。现在印
   「台账：N 个议题在跟，无到期未建卡；无退役候选（建卡满 30 天起算）」。
   承诺与实现分家，是这次第二个被顺手抓到的东西。
4. ② 段同样先过 `_load_backlog_full`。

## 后果

- 从今晚（10-31 21:00）起，简报 ④ 段会出现「台账：N 个议题在跟，无到期未建卡；
  无退役候选」这一行——**它证明这两条线真的跑过**，而不只是代码里存在。
- **退役仍然只是候选**：`retired` 列出后要人改 `status: retired` 才生效，
  机器不自动退役（ADR-0007 保留）。8 张卡里最早的是 10-14 建的，
  11-13 之后 `ai-tool-benefits-…`（唯一一张从未成文的）会第一次出现在候选里。
- 没有改阈值（30 天），没有改 `retire_candidates` 的判据——它本来就是对的。

## 一条留给测试纪律的

新加的用例**故意用生产形状的输入**（只有 `threshold/due/open_issues`、没有
`issues`）去断言「到期未建卡」必须印出来。这类「夹具与生产形状不一致」的洞，
只能靠「拿真实输入跑一遍」发现——读代码时它看起来是对的，因为代码里每个字段
都被读到了，只是那个字段生产里是空的。
