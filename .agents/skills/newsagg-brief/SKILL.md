# newsagg-brief — 简报层

把人机接口生产出来。设计依据 [ADR-0019](../../../docs/adr/0019-triage-edge-cases-and-brief-structure.md)、[ADR-0005](../../../docs/adr/0005-github-issues-for-brief-and-alerts.md)、[ADR-0006](../../../docs/adr/0006-runtime-shape-schedule-watchdog-budget.md)。

## 执行

```bash
# 写入 reports/<日期>.md
python3 .agents/skills/newsagg-brief/scripts/brief.py

# 只打印，用于预览或调试
python3 .agents/skills/newsagg-brief/scripts/brief.py --stdout
```

它读取当日各阶段产物（均在被 gitignore 的 `.newsagg/` 下）：候选、分拣决策、发布台账。**缺失时按"该阶段未运行"呈现，不报错**——因为简报本身必须无条件产出。

## 五段结构（固定，ADR-0019）

| 段 | 内容 | 特别要求 |
| --- | --- | --- |
| ① 今日结论 | 发了什么 / 弃权及原因 | **弃权必须显式声明**，用于与"系统没跑"区分 |
| ② 采集与分拣概览 | 采集量、源健康、低置信度、无卡可接、排序说明 | 低置信度与无卡可接**都必须呈现** |
| ③ 本篇与发布结果 | 事件、接卡、新在哪、待处理成稿、dry-run 提示、**已发表文章的表现** | 待处理成稿标注"不重发" |
| ④ 资产变动 | 卡总数、新建/修订、退役与合并建议 | 治理建议等你否决 |
| ⑤ 需你介入的事项 | 熔断、清理草稿、教学副本、信源失效、**自动降频、表现数据读回失败** | 无事项时写"无" |

## 硬规则

1. **简报必须每日存在，弃权日也要发。** 它是 ADR-0006 心跳机制的依据：看守检查"今日简报是否存在"，缺失即告警。若弃权日不发简报，看守无法区分"今天没选题"与"系统死了"。

2. **① 段必须显式写出结论**，包括弃权。"无决策记录"与"弃权"是不同的表述——前者是异常，后者是合法结果。

3. **熔断优先呈现。** 若当日发布环节失败，① 段直接呈现熔断状态，不呈现常规结论。

4. **必须区分"列表为空"与"解析失败"。** 各阶段产物缺失时按"未运行"呈现，不静默当作"无内容"。

5. **① 段必须区分"降频跳过日"与"系统没跑"。** 降频跳过日会刻意不产出决策文件，若不特判就会写成"无决策记录"——那正是 ADR-0019 要求区分开的异常表述。因此 ① 段须显式写「降频跳过日」并给出解除方法（ADR-0037）。

6. **降频与读回失败必须告警，不能静默。** 自动降频让系统在变差时**变得更不活跃**，产出下降本身会掩盖问题的严重性；表现数据读回失败则让排序参考与降频判据悄悄过期。两者都进 ⑤ 段（ADR-0010 要求「必须靠告警补偿，否则静默滑向长期停摆」）。

7. **dry-run 必须提示清理草稿。** 它会在真实账号留痕（ADR-0032）。

## 输出与双写

- `reports/<日期>.md`（入库，随 git 可追溯）
- GitHub Issue（可选，供评论与通知）——**issue 是人机交互界面，markdown 是历史档案**（ADR-0012）

Issue 命名约定（ADR-0020）：标题固定为 `NewsAgg 简报 YYYY-MM-DD`，带固定 label。看守按**标题 + 日期 + label** 判定存在性，并校验五段齐备（因而能发现"存在但残缺"）。已处理的简报由本人**手动关闭**，关闭即"已读"信号。

## 与其他阶段的接口

- **上游**：采集（`newsagg-collect`）、分拣（`newsagg-triage`）、发布（`newsagg-publish`）的产物。
- **下游**：看守（GitHub Action）读它判存活；本人读它做否决与教学。
- 简报是**所有需要人否决的机制的提交处**：退役/合并建议、风格提议、熔断、待处理成稿都在这里。
