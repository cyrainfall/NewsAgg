# 自愈补采救得了候选池，救不了趋势信号

## Context

2026-10-29，白天三次定时采集（08:00 / 13:00 / 18:00）一次都没有落盘：
`.newsagg/candidates/2026-10-29.json` 不存在，`.newsagg/` 下全天**零文件写入**
（`Get-ChildItem .newsagg -Recurse -File | Where LastWriteTime > 当天零点` 返回空）。
触发本身是有的——三条提醒都到了宿主，但那些回合没有产出任何产物。

21:00 的主流程以 `--no-collect --publish` 启动。第 1 段的 ③ 检测到今日候选池不存在，
按设计自愈补采：268 条抓取 / 104 条保留 / 6 源成功 / 1 源失败（github）/ 陈旧源 0 /
`runs_today: 1`。第 2、3 段正常跑完，**真发了一篇**（`verdict: title_found`）。

也就是说：从「系统有没有跑完」这个角度看，这一轮是成功的，自愈补采把该救的都救了。
本文记的是它**没救到的那一部分**。

## 发现：候选池和趋势信号的上游是同一个，但需求不同

分拣输入包的 `trend_summary` 是这样的：

```json
{"snapshots": 6, "by_state": {"climbing": 0, "steady": 0, "cooling": 0,
 "unknown": 104, "absent": 0}, "by_position_source": {"hot": 101, "none": 3},
 "note": "本池没有任何条目能算出趋势（快照 6 个、可算条目 0 条）——这**不是**
          「大家都很稳」，是「还看不出」。排序请退回当前热度。"}
```

对照 2026-10-28（白天采了 3 次）：**102 / 156 条可算**。同一个算法，两天的覆盖率是
98% 对 0%。差别不在算法，在**白天采了几次**。

因果链很短：ADR-0056 定义 trend 需要**同源 ≥2 条观测**才能算出位次变化；而生产上这
第 2 条观测**只可能来自白天的另外两次运行**——自愈补采每轮只跑一次，它的作用是把
候选池补到今天，不是把时间轴补出来。几个 `snapshots: 6` 是**按源**计的（6 个源各 1 条），
不是按时间：快照个数看着不少，可算条目仍是 0。

所以「自愈补采」这个名字容易造成误读。它自愈的是**候选池的有无**，不是**信号的分辨率**。
今天这条链路第一次把两者的差别摆出来：

| | 白天采 3 次（10-28） | 白天 0 次（10-29，靠自愈） |
| --- | --- | --- |
| 候选池 | 282 条 | 268 条（自愈，够用） |
| trend 可算 | 102 / 156 | **0 / 104** |
| 能不能发 | 能 | 能（真发了 1 篇） |

功能没有损失——trend 按 ADR-0056 只参与排序、不打分、不设门槛，退化时退回
「当前热度 + 卡匹配度」。损失的是**分辨率**：这一天没有任何「谁在往上爬」的信息，
只能按存量热度排序。而且它**不会报错、不会降级提示、不会失败**——`by_state` 里整齐
地写着 104 个 `unknown`，一个不看 note 的人会以为「今天大家都很稳」。

## 决定

1. **不为 trend 补第二次采集。** 一轮里连着采两次，两次间隔只有几分钟：上游榜单不是
   每几分钟刷新一次，那个「位次变化」几乎全部是抓取时刻的抖动。为了让覆盖率好看而造
   观测，是把噪声升级成信号——比没有信号更糟，因为它会被下游当成事实排序。这与
   ADR-0081 的教训同型：**指标能被消费之前，先确认它测的是真的要测的东西。**
2. **退化必须在简报里读得出来，而不是只在输入包里。** 本轮的 `note` 已写
   「不是『大家都很稳』，是『还看不出』」，`by_state` 全量打印，简报②段也有一行
   「本轮 trend 不可用：…已退回当前热度 + 卡匹配度排序」。这三处是刻意重复的：
   输入包给人看的概率最低，简报才是心跳。
3. **把这条耦合计入残余风险**（`DESIGN.md` 87）：trend 的覆盖率是**当天采集次数的
   函数**，不是算法质量。白天采集缺席的日子，排序口径就退化一档，这是可接受的降级，
   但要被知道。
4. **记录自愈补采的边界写法**：将来若有人想「让 ③ 多采一次以补齐 trend」，先读本文
   第 1 条。

## 未做

**采集缺席没有告警。** 今天这次只能从「简报②段写着今日采集 1 次」倒推出来，而那需要人
主动去读那一行。可以做的是：连续 N 天 `runs_today == 1`（即只有自愈那一次）时，把
简报①段升级成一句明确的警告。没有现在做的理由：`runs_today` 是现成的，但「连续 N 天」
需要一个跨天状态，而 `.newsagg/run-status.json` 只存最后一次——要做得先定状态存在哪，
那是另一个决定，不该塞进本文。
