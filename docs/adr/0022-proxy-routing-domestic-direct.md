# 代理分流：头条与国内源直连，仅境外源走代理

## Context

用户提供了可用的 VPN（polarisnet 订阅；本机客户端实为 **Clash Verge**，见 ADR-0027 的事实修正），因此境外信源变得可达。

这解锁了 ADR-0021 中因网络不可达而受限的能力：`github`、`exa_search`、`youtube`、`reddit` 等 tier-0/1 渠道可用于写作阶段的扩展检索，而这些渠道与"AI 与开发者工具"赛道高度相关。

但它同时引入一个**会精确制造封号条件的风险**。这与 ADR-0001/0009 已接受的风险性质不同：那两个是被迫承担的代价（没有官方 API、必须用浏览器），而这个是**白送的**——没有任何收益交换。

具体机制：本人的头条号是在国内住宅网络下注册并登录的；ADR-0001 引用的调研已明确提到平台存在 **IP 段检测**（"Creators report device-fingerprint, IP-segment and publishing-timing-regularity detection"）。若发布流量突然从境外出口发出，"同一设备指纹 + 国家/地区突变"是账号共享或凭证被盗的典型画像，叠加 argus 指纹风控，风险显著高于 ADR-0009 已接受的"数据中心 IP"。

另一个必须澄清的误解：**VPN 不能解决 ADR-0009 遗留的"数据中心 IP 特征"问题**——境外节点只会让它更糟。代理的用途是**取境外信源**，不是发布。

## Decision

**一分流。** 头条及所有国内源 `DIRECT`，仅境外源走代理：

```yaml
rules:
  - DOMAIN-SUFFIX,toutiao.com,DIRECT        # 发布与数据读回，绝不走代理
  - DOMAIN-SUFFIX,byteimg.com,DIRECT
  - DOMAIN-SUFFIX,snssdk.com,DIRECT
  - GEOIP,CN,DIRECT                          # 国内信源（微博/知乎/36氪/掘金/IT之家等）直连
  - MATCH,PROXY                              # 仅境外源走代理
```

**二代理跑内核，不跑 GUI。** 服务器上运行 **mihomo (Clash.Meta) 内核 + systemd**，使用与桌面客户端同一份 polarisnet 订阅。桌面客户端（Clash Verge，`verge-mihomo` 内核）是图形应用，在无桌面服务器上无意义。分工是：**GUI 客户端面向本人的桌面，裸内核面向服务器**。

**补充（核实订阅后修正）**：机场订阅本身**已内置完整的头条域名族分流**，全部指向国内直连（见 ADR-0027）。因此本 ADR 的规则从"唯一手段"降为**兜底**——既有规则更完整，但仍需验证其确实生效。

**三凭证边界。** 订阅链接按 Q81/Q102/Q115 同一原则放入 ECS 的 `.env` 并 gitignore；仓内只留 mihomo 配置模板（分流规则）与 `.env.example`。订阅链接泄露等于 VPN 被白用且节点可能被封。

**四模型流量按同一规则分流。** 分拣优先使用国内模型（DeepSeek/Qwen/GLM 等，直连低延迟、省代理带宽），写作使用强模型。两者都遵循上述分流规则。

**五代理失效不熔断。** DailyHotApi 覆盖的国内源（微博/头条/知乎/36氪/掘金/IT之家/CSDN）不需要代理，因此代理不可用时**降级**为"采集面变窄"并进入简报，而非停止运行——与 ADR-0021 的信源健康处理一致。

## Consequences

- **分流规则的正确性成为发布安全的一部分。** 一条误配（如 `MATCH,PROXY` 排在 `toutiao.com` 之前）就会让发布走境外出口。因此分流规则需要可验证，不能只靠肉眼审阅。
- mihomo 内核成为云服务器上的常驻进程，占用内存（与 ADR-0023 的 2GB 约束叠加）；但它是轻量的（Go 编译，通常几十 MB 量级，远小于 Chrome）。
- 使用同一份订阅意味着订阅失效会同时影响桌面与服务器，且订阅可能是单设备或有限设备限制——这一点需实际使用中确认。
- 分拣用国内模型使该环节不受代理抖动影响，但分拣与写作因此走**不同供应商**，两者的输出风格与指令遵循习惯不同，提示词需要分别调优（与 ADR-0020 的分层选型一致）。
- 境外信源明确为**增强而非前置**：即使代理长期不可用，流水线仍能基于国内热榜运行，只是深度信源缺失。这保住了"代理不是单点故障"这一性质。
