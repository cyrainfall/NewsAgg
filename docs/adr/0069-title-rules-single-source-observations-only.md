# 标题规则写成一份文件、一处实现；观察项只打标签不拦发

## Context

2026-10-26 用户要求「用 websearch 搜索看该如何提交提高点击率」，随后要求「诊断」，
最后要求把结论落成可执行产物（「要」）。

诊断的结论很直接：10 篇文章合计展现 8013、阅读 20，**点击率 0.25%**；
公开资料给的推荐线是「<5% 停止推荐、8~20% 正常」。后台作品管理页显示
10 篇状态全是「已发布」、每篇都带「首发」标识——**不是限流**。
10-20 那篇《Codex搬走Cursor配置：选AI编程工具的标准变了》完读率 30.86%、
「超过 96% 同类作品」，而点击率只「超过 2% 同类作品」。平台替我们把结论说完了：
**内容留得住人，标题拉不来人**。

但「标题该长什么样」这件事，我试过三条路，全都没走通：

1. **从站内搜索结果挖特征**（71 条样本，两次分组统计）：所有特征在高互动组和低互动组
   **都不分离**。原因是展现量本身受账号权重、发布时间、首发与否影响——
   搜索结果里高展现的是大账号的老文章，不是标题效果。**已证伪。**
2. **抄「爆款标题公式」**（疑问型/反差型/借势型/干货型）：来源是情感心理类，
   与本赛道没有共同样本。**未采用。**
3. **沿用现有纪律「明确对象 + 读者利益点」**：0 阅读的四篇里有三篇对象极明确
   （拼豆App、DeepSeek单卡账本、Meta 8160亿参数模型）。**已验，无效**——
   「对象明确」不等于「读者有理由点」。

第 4 条路是「从我们的搜索结果里找规律」，但样本 n=10，且展现量与账号权重共线
（10-21 那篇只有 18 展现却有 11.11% 点击率），**任何标题结构假设在这 10 个数里
都验不出来**。

所以这份规则能做的只有两件事：把**能机械判定**的底线变成机器闸门，
把**还不能判定**的假设变成每次发布都记一笔的标签。

## Decision

### 一、规则本体放在 `platforms/title-rules.md`，归本人

ADR-0018 的所有权表里 `platforms/` 归本人（理由：合规与风格规则需人工复核以免过期）。
这份文件是规则的**唯一副本**。机读部分嵌在 HTML 注释里：

```
<!-- title-rules:json { ... } -->      硬下限，publish.py 按它拒发
<!-- title-rules:observe { ... } -->    观察项，publish.py 打标签进账本
```

### 二、判定逻辑只写一份

`title_rules.py` 放在发布层脚本目录，`publish.py`（拒发）与 `build_brief.py`
（渲染进选题包）都从它加载。**两边不各抄一份。**

这是 ADR-0042 的教训重演：契约有两份实现时它们会漂移，而且漂移是静默的。
标题规则如果有两份实现，一份加了一个禁用词、另一份没加，
表现是「有时候拦有时候不拦」，极难归因。

### 三、硬下限只有三条

| 编号 | 规则 | 依据 |
|---|---|---|
| H1 | 长度 2~30 字 | 头条平台硬限制 |
| H2 | 不含禁用词 | `.wewrite/style.yaml` 的 `blacklist` |
| H3 | 不含标题党词 | 头条审核对夸大标题敏感 |

**H3 为什么是硬拦而不是「建议少用」。** 头条审核规则里「标题夸张」与敏感词同属退回项，
而**退回的文章再改也不会被推荐**（woshipm 拆解的推荐机制第一关）。
所以夸张标题的下行风险不是「少一点点击」，而是「这一篇直接归零」。
账号是第 12 天、0 粉丝、信用分未知的新号，月发 1 篇——
一次归零等于损失四分之一产能。保守是划算的。

### 四、观察项只打标签，绝不拦发

观察项（人群落点 / 反差结构 / 具体数字 / 不以裸百分号结尾）**不拒发**，
只在发布时打进账本的 `title_tags`，等样本攒够 20~30 篇再回来看哪一条值得升为硬下限。

**这里有一个本轮真实发生、必须记下来的坑。** 写规则时我先把「不得以百分号结尾」
列成了硬下限 H4。接线后一测，**它拦掉的是 10-25 真实发过的那篇**
《想靠 AI 做副业的人：年入 10 万美元的只有 2.4%》。它的全部证据是一个直觉，
没有任何实测支撑。而同一份文件里第二节点着一句原则：

> 现在不升为硬下限，是因为一个把错规则做成硬门的系统，会在你还没发现它错的时候
> 就把文章全拦下来。

自己写下这条原则、转头就违反它，是最坏的一种违反——因为它伪装成「严格执行」。
所以 H4 降级为观察项。**一个被自己写下的原则当场抓住的错误，比十个没人发现的错误更值钱，
因为它证明了这条原则是可执行的。**

### 五、观察项的假设方向多数是反的，如实记下来

把打标签器接上、拿 10 篇真实数据跑一遍之后，发现三条观察项的假设**方向多数是反的**：

| 标题 | 点击率 | 人群词 | 反差 | 数字 |
|---|---|---|---|---|
| 老板叫停AI裁员，中间层位已经换成外包 | 11.11% | ✓ | ✓ | ✗ |
| Codex搬走Cursor配置：选AI编程工具的标准变了 | 0.96% | ✗ | ✓ | ✗ |
| AI视频省下的成本，正被模型厂商收走 | 0.73% | ✗ | ✗ | ✗ |
| AI 提效写进绩效，先涨的是你的返工率 | 0.27% | ✓ | ✓ | ✗ |
| DeepSeek搜索5元一千次，做Agent的成本要重算 | 0.17% | ✗ | ✗ | ✓ |
| Meta 开源 8160 亿参数模型：模型免费，运维不免费 | 0.00% | ✗ | ✗ | ✓ |
| 拼豆App三个月43美元：AI小工具死在留存 | 0.00% | ✗ | ✗ | ✓ |
| 想靠 AI 做副业的人：年入 10 万美元的只有 2.4% | 0.00% | ✓ | ✗ | ✓ |

点击率最高的 0.96% 与 0.73% 两篇**三条观察项全不命中**（反差词表里没有「收走」）；
0.00% 的三篇里两篇命中「有数字」；0.73% 那篇还命中了反面词「成本」。

**结论：当前 n=10 不足以支持任何标题结构假设。** 这不是「假设错了」，是「样本根本测不出来」——
展现量与账号权重、发布时间、首发与否共线，这 10 个数之间的差异可能全部来自账号权重。
所以观察项的价值不在「照着写」，而在「每次发布都留一份标签」。

### 六、失败的路要写进文件，不只写在脑子里

`platforms/title-rules.md` 第三节专门记录上面那三条已证伪/未采用的路。
理由：下一轮写标题时，最容易被重新提出来的恰恰是那些**看起来最合理**的路
（「去扒爆款标题特征」），而不是没人想得起来的路。把反证写在文件里，
下一个人（包括下一个我）读到就不用重新试一遍。

## Consequences

- **发布门多了一道会拒发的检查。** 收益是避免「标题夸张 → 审核退回 → 永不再推荐」
  这条不可逆的路径；成本是万一规则定得太紧，会白白挡掉一篇。H3 的词表尽量保守，
  只收明确属于标题党的词。
- **规则读不上时不阻断发布。** `publish.py` 在规则文件缺失或解析失败时
  **只按平台硬长度限制放行**，并打印一条 warning。理由与 ADR-0062 判据一致：
  规则读不上 = 失去检查能力，不等于必须停工——但必须让人知道。
  这个 warning 目前只出现在 stdout，**没有进简报**（见残余风险）。
- **账本多了一个字段 `title_tags`。** 它写 `null` 而不是省略：
  省略与「没打标签」在消费端不可区分。
- **这套规则解决不了「谁会看到」。** 92.63% 的曝光来自推荐频道；
  平台自述的低推荐原因包括「话题过于冷门」「账号内容垂直度较低，
  机器算法会重新识别分类再进行推荐，时间上会延长」。标题只决定**被推了之后点不点**。
- **规则文件有四个自然语言副本的问题。** 与 ADR-0050 记录的赛道定义同型：
  `platforms/title-rules.md`、`.wewrite/style.yaml` 的 blacklist、
  `build_brief.py` 渲染的段、`publish.py` 的门。
  这次至少做到了「判定逻辑只有一份」，但**词表与语义仍然是两处**（`style.yaml` 的
  blacklist 与 title-rules 的 forbid_words）。
