# 阶段 0 落地决策变更：写作降级、封面模板化、认知写回时序

## Context

按 ADR-0027 实施阶段 0 时，三处此前的设计决策在实际落地中发生了变化或被证实。记录于此，以免文档与实现分叉。

## 变更

### 一、写作走「agent 自写」降级路径（不配置写作模型 key）

`wewrite llm-write` 的凭据要求为 `WEWRITE_WRITER_API_KEY`；未配置时**退出码 3**，而其 docstring 明确定义该码为"降级为 agent 自写"。

本人选择**不配置**该 key，因此写作始终走 agent 自写。

**代价（明确接受）**：`llm-write` 存在的理由是"关键省钱点——正文走文件→文件，stdout 只回简短摘要，绝不把大段正文回灌编排 agent 的上下文"。放弃它意味着**每次写作都消耗编排上下文**，长文尤甚。因此本决定与 ADR-0006 的 $5/日 预算上限有张力：agent 自写的成本结构是上下文滚雪球，而非按次计费。

**保留的接口**：brief 生成（`build_brief.py`）不受影响，它产出的 brief 对两条路径都适用。若日后配置 key，无需改代码。

### 二、封面走模板拼图（不使用 AI 生图）

ADR-0013 原定封面兜底链为「AI 生图 → 模板拼图」。因未配置图片 provider key，当前**只使用模板拼图**。

实现为纯 PIL 绘制（`make_cover.py`，1200×675，深色科技感，含 AI 标识脚注）：
- 不联网、不启动浏览器，因此在 ADR-0023 的 2GB 约束下开销可忽略。
- 已目视验证渲染正确（CJK 可读、16:9、脚注存在）。
- 符合 ADR-0013 的"不用新闻原图"（版权风险）。

**保留的接口**：ADR-0013 的兜底链未变，只是当前起点是模板而非 AI 生图。若日后配置 provider，可插在模板之前。

### 三、认知写回的时序约束在实现中被显式固化

ADR-0026 规定"认知写回必须在发布成功之后"。实现 `writeback.py` 时，此约束意味着：**dry-run 不得触发写回**。

因此本轮虽然完成了完整的三态决策与成稿，但**没有向任何观点卡写回**——因为只跑到 dry-run。这是设计意图，不是遗漏。`writeback.py` 以 `--dry-run` 模式验证通过（覆盖 `covered_events: []` 展开、`last_written` 替换、修订史追加三条路径），但未对真实卡执行。

## Consequences

- **agent 自写的成本结构未被验证。** 与 `llm-write` 的"不回灌上下文"相比，自写的上下文成本随文章长度线性增长。$5/日 上限是否够用，只有连续运行若干天后才知道。若超限，降级行为是"只跑分拣不写稿"（ADR-0006），即当日弃权。
- **模板封面的效果未经外部验证。** 目视正确不等于点击率可接受。它是 ADR-0013 已接受的"放弃图片与事件相关性"这一质量代价的具体体现。
- 三处变更都是**"先用能跑通的路径，保留接口"**，而非推翻设计。因此它们不改变任何 ADR 的决策，只改变当前实现起点。这是有意的：在验证阶段，可用性优先于最优性。
- `writeback.py` 的三条路径已被 dry-run 覆盖，但**发布成功后是否真的写回、写回内容是否准确，仍是未验证的**。它属于阶段 0 尚未闭环的部分。
