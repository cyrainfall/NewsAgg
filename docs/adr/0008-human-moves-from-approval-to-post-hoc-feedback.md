# 无人值守把人的角色从审批改为事后反馈

## Context

系统两次选择了无人值守自动发布（ADR-0001）。这与多份既有资产的前提直接冲突，冲突点不只是发布权限，而是**人在循环中的位置**：

- `xiaohongshu-skills` 的 `xhs-publish` 把"发布前必须让用户确认最终标题、正文和图片"写成必做约束。
- `wewrite` 的状态契约默认 `permissions.publish: false`，规则是"只有用户明确要求发布才为 true"。

也就是说，被复用的两套资产都建立在"人在发布前出现"这一前提上。无人值守取消了这个前提，于是必须回答：人还需要出现吗？出现在哪里？

## Decision

人不再出现在发布之前，而是出现在**发布之后**。具体地：

- **发布前的门是自动质检**，不是本人审批：`wewrite-review` 的编辑决定与 `content-scorer` 的评分为准。
- **本人的角色是事后反馈**：文章发出后，系统保存一份**教学副本**，本人对它的修改即风格资产的输入信号（保住改稿飞轮），本人的反应亦回流到观点卡。
- **熔断仍然需要人**：登录失效、发布被拒、限流时暂停自动发布并告警等待人工介入。因此"人不在发布前"不等于"人不在任何地方"——人在异常路径上。
- **失败时成稿不丢也不自动重试**：保留为"待处理成稿"并标入简报，由人恢复后自决。

## Consequences

- **风格资产在无人值守下会失去输入源，除非显式补回。** 原设计中改稿飞轮的输入是"发布前本人的修改"，而那个环节已被取消。教学副本是对这一缺口的补救；若本人长期不去修改教学副本，飞轮实际停摆，风格资产将停留在冷启动状态。这是本决定最容易被忽略的代价。
- 自动质检成为唯一的质量门，因此它的可靠性直接等同于产出质量。它放行一篇差稿的代价比有人审批时更高，因为差稿会直接公开发布。
- "人的接受度"从发布门槛降级为事后信号，因此它无法阻止任何一篇发布——这正是采纳无人值守的应有之义，但意味着**质量事故的最坏情况是公开可见的**。
- 简报因此承担了额外职责：它不只是报告，也是人介入的唯一入口（待处理成稿、退役与合并的建议否决、熔断告警都在其中）。
