# 已发布内容不可自动修改，错误进入简报由人处置

## Context

ADR-0008 取消了发布前的人工审批，因此**错误会直接公开发布**。这带来一个此前未回答的问题：发布之后如果发现事实错误（引述错误、数据过期、来源不可靠），系统该怎么办。

这里有一个与"熔断"的关键区别：熔断处理的是**发布失败**（内容没发出去）；本 ADR 处理的是**发布成功但内容有错**——后者更隐蔽，因为流水线会认为一切都正常。

同时，自动编辑或删除已发布内容本身是高风控信号（平台会把异常的自动删改行为视为可疑），而且"自动改正"需要有人校验改正是否正确，否则可能越改越糟。

## Decision

**不自动删改已发布内容。** 发现错误时写入简报，由本人决定撤回、修正还是不予处理。

## Considered Options

- **系统自动修正或删除重发**：会引入高风控信号，且在无人校验的情况下自动"改正"可能制造更大的错误。
- **在下一篇文章里声明更正**：对读者透明，但在无人值守下等于把错误再传播一次，且系统未必能可靠判断"哪篇该带更正"。

## Consequences

- 系统对已发布的错误内容**没有自愈能力**，唯一的补救路径是人读简报后介入。因此简报中的"错误"条目是本设计里唯一无法自动化的一类告警。
- 这一决定与 ADR-0008 是一致的：既然接受"发布前无人审批"，就必须同时接受"发布后无人自动纠错"。两者是同一个取舍的两面，不能只取其一。
- 因此**发布前的自动质检与合规门的可靠性，直接决定这个决定的代价**。质检放行的错误越多，人工介入的负担越重，而介入路径只有简报这一条。
- 由于错误只能靠人发现，系统应当尽可能主动暴露可疑之处（如来源未核实、数据仅单一来源），把它作为简报的一等内容，而不是等本人自己去看文章。
