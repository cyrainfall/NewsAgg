# 闸门拒绝被渲染成「运行失败」，而简报教人去重跑

## Context

2026-10-31 21:00 的主流程三段都跑通了：采集 268 条 / 预筛 159 条、分拣判定
`continue`（接 `personal-ai-monetization-is-paid-demand-not-technology`）、成稿
`outputs/2026-10-31-ai-content-price-anchor-is-zero.md` 写完、封面渲染完成。

发布被拦下，理由是 **ADR-0014 的每日 1 篇**——当天额度已经被 00:33 那次
「10-30 成稿改稿重发」用掉了（`gid 7702500080871391771`）。闸门按设计工作，
这一轮**正确地没有发出第二篇**。

问题出在它被怎么报出来。

## 发现：同一件事在两层被说错

`publish.py` 拒绝发布时打印得很清楚：

```json
{"ok": false, "stage": "daily_limit",
 "message": "今天（2026-10-31）已发布 1 篇，达到 ADR-0014 的每日上限 1 篇……"}
```

但编排器只取了退出码：

```bash
"$PY" .agents/skills/newsagg-publish/scripts/publish.py ... 
PUB_RC=$?
if [[ $PUB_RC -ne 0 ]]; then
  fail_soft "publish" "发布未成功（退出码 ${PUB_RC}…）" "$SLUG" 1
fi
```

`stage` 就地丢掉了。`run-status.json` 于是写下 `stage: publish / ok: false`，
而 `brief.py` 的两处渲染都以 `ok == false` 为唯一判据：

- ① 段：**「本轮运行未完成」……「系统在运行途中失败了」**
- ⑤ 段：**「产出可能不完整。修复后重跑：`run_all.sh`」**

于是「闸门按设计拦下了第二篇」被写成「系统挂了，请重跑」。这句话的两种执行方式
都是坏的：

1. **照它重跑** —— 仍然会被同一个闸拦下（当天额度已用），白跑一轮；而且重跑本身
   就是「对发布的重试」，与 ADR-0059 的铁律相抵。
2. **把闸门去掉再加 `--allow-daily-override`** —— 那就是**重复发文**，平台明令禁止。
   ADR-0059 已经为这个动作付过一次代价（真发了一篇重复文章）。

这条链路上没有任何一处报错：退出码是对的、JSON 是对的、简报也成功写出来了。
错的只是**这次拒绝被叫作了什么**。它与 ADR-0042（`kept_new` 读成空）、
ADR-0047（失效源不显示）、ADR-0081（闸门空转）同型：**错的地方不报错，
报错的地方说错原因。**

## 决定

三处改动，一处也不改发布行为：

1. **编排器保住 stage**（`run_all.sh`）。publish 的输出同时进 `tee` 与临时文件，
   退出码非 0 时先认这一个 stage：命中 `daily_limit` 就改用
   `fail_soft "daily_limit"`，并在 reason 里写明「闸门按设计拒绝」；其余情况
   照旧报 `publish` 失败。只认一个 stage 是刻意的——多认会让「真失败」有机会
   被误判成「设计内」。
2. **简报分开渲染**（`brief.py` ① 与 ⑤）。`daily_limit` 写成「今日额度已用尽，
   本轮未发布」，并显式写两句：**不是故障、不是弃权**；**不要重跑、不要加
   `--allow-daily-override`**。⑤ 段给的是处置而不是修复：「明天首条通道补发，
   或留作教学副本」，并提醒两种都做会撞同一个闸。
3. **测试钉住渲染**（`tests/test_brief_daily_limit.py`，5 个用例）。关键是两条
   **反向断言**：`daily_limit` 的文本里**不得出现**「本轮运行未完成」「系统在
   运行途中失败了」「修复后重跑」；真故障（`stage: publish`）**必须保留**
   「修复后重跑」——否则这条特判一旦写宽，就会把真失败也吞掉。

## 后果与边界

- 记录更正过：`run-status.json` 的 `stage` 从 `publish` 改为 `daily_limit`，
  并留 `note` 说明这是**改记录不是重跑**。本轮没有重试发布。
- 这条修的是「怎么说」，不是「怎么办」：**额度仍然会撞**。跨零点运行会吃掉次日
  额度，这是 ADR-0014 按日历日计量的已知副作用，四天内出现两次（10-28、10-31），
  第二次的起因是「零点后改稿重发」而不是新文章。要不要把额度口径改成按
  **内容日**（slug 的日期）计、或禁止零点后的重发，是另一个决定，未做。
- 未做的另一半：`publish.py` 的拒绝记录**没有进发布账本**，所以简报只能从
  `run-status.json` 读到它，事后想复盘「哪些天被闸拦过」在账本里查不到。
  接上它需要给 publish.py 加一个「拒绝也落账」的路径，那会动账本的语义，
  不在本轮范围。
