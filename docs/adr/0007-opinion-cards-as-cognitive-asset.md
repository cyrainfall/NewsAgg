# 观点卡作为认知资产：只追加、可修订、发布后回写

## Context

系统的复利承诺是"输出的内容会慢慢沉淀，为下一次输出做准备"。这要求一个形态明确的记忆载体。ybrain 的"知识包"是最接近的先例：同一主题持续追加到同一篇活文档，而不是每次新建。

但直接照搬会出问题。ybrain 的知识包装的是**关于某个主题的事实**；本系统的观点卡装的是**判断**，而判断会被本人推翻。严格的"只追加"会让一张卡在改变立场后只是长出一条自相矛盾的尾巴，读者（下一次运行的模型）无法分辨哪条是当前判断。同时"新文章不得另起"在冷启动第一天就无法成立——那时一张卡都没有。

## Decision

观点卡是认知资产的组成单位，采用如下形态：

- **卡片即议题。** 事件上升为议题的抽象发生在**分拣阶段**，不在写作阶段。因此分拣的输出天然对应一张卡的状态：跳过（卡已含此事件且无进展）、续写（卡已存在且这是新进展）、新写（需要新卡）。
- **卡片记四样东西**：当前判断、依据事实、修订史、已覆盖事件。第二项支撑"新在哪里"，第四项支撑"跳过 vs 续写"的判定——分拣层无法从散文正文里可靠推断"哪些事件已写过"。
- **判断变化时追加修订记录**，说明观点如何演变，不改写旧判断。这与"活文档"是同一规则：卡片记录判断的历史，不是"当前正确答案"的快照。
- **允许自主建卡，但受新建门槛约束**：一条判断必须能接住未来的新闻，而不只是支撑当前这一个事件；且每日新建数量有硬上限。若任何事件都能凭空建卡，Q1 的"用已沉淀认知二次过滤"就会退化为"是否在赛道内"。
- **发布后自动写回**：成稿后把"新增判断 + 本次依据"作为一条修订追加回对应卡，并带**未复核**标记与来源（哪篇文章、何时、发布状态）。这是"越写越强"的实际闭环点；没有它，系统只会重复劳动。写回不阻塞，但本人事后提出异议时该条修订被标为**已推翻**并追加更正——机制细节见 ADR-0026。
- **允许治理**：两张实为同一议题的卡可以合并；长期接不住任何新闻的卡可以退役。两者都写入简报供事后否决。治理是必要的，因为分拣要全量读卡，只增不减的卡库会让成本单调上升。

## Considered Options

- **卡片只记判断正文，其余靠 git history**：人写起来最轻，但分拣层无法可靠知道"哪些事件已写过"，续写判定会不可靠。
- **结构化 frontmatter 为主（判断/置信度/事件 id）+ 正文**：可程序化比对，但把判断拆成字段后写起来僵硬，与"活文档的自然阅读感"冲突。
- **完全不允许建新卡**：与冷启动和真正的新议题都冲突。

## Consequences

- 卡片是分拣层的唯一读入，因此它的结构直接决定分拣能判到什么精度——这是全系统最承重的数据契约。
- "已覆盖事件"这一字段使卡片成为**唯一**能防重复发文的地方，而防重复在无人值守下同时是风控措施。
- 退役使分拣成本可控，但也意味着认知资产会**被有意丢弃**：一张退役的卡承载的判断不再参与匹配。这个损失是自觉接受的，换取了成本的可预测性。
- 冷启动必须人工植入种子卡（手写 3–5 条粗判断，由系统扩成卡），否则允许弃权的规则会让系统在积累出第一张卡之前几乎不产出。
