# NewsAgg 信源渠道策略（部署级）
#
# 这个文件回答的问题是：**这台机器上，哪些信源渠道是能用的？**
#
# 为什么要单独一份文件：渠道可用性不是代码属性，是**部署属性**。
# 同一份代码在一台有代理的机器上能用 Jina Reader，在没有代理的机器上
# `r.jina.ai` 直连不通。把这件事写进代码，等于把某一台机器的网络
# 硬编码进整个系统；写进这份文件，就变成「部署时声明一次，运行时读」。
#
# 格式：一行一个规则，字段用 `|` 分隔（不要用 YAML/JSON——多一行依赖
# 就多一个「机器上没装」的机会，ADR-0076 的教训）。
#
#   <渠道名> | <状态> | <理由>
#
# 状态取值：
#   enabled  —— 正常用
#   disabled —— 明确不可用。运行时会**主动检查**并在简报第 ⑤ 段说明
#               「这个渠道今天不用」以及为什么，而不是让它带着绿色状态
#               悄悄失效（ADR-0059 残余风险 53 的正是这件事）。
#
# 判据：一个渠道被标 disabled 的唯一理由是**在这台机器上实测过不通**，
# 不是「我觉得它不通」。理由要写清楚是哪台机器、怎么验的。
#
# ── 当前部署（2026-10-28 起，ADR-0079）──────────────────────────────
# 唯一生产环境是本机 Windows（Clash Verge 在 7897）。Jina Reader 在本机
# 实测可用，因此**没有任何渠道需要声明为 disabled**——这也意味着本文件
# 目前不生效任何规则。留空是有意的：它不是"待填的模板"，而是"这台机器
# 没有关掉任何渠道"的事实陈述。
#
# 历史上这里曾有一行 `web | disabled | 服务器上实测 r.jina.ai 直连不通`，
# 那是服务器部署（ADR-0077/0078）的事实。服务器已于 2026-10-28 退出生产
# 角色并被清空，那一行随之失效——留着它会让本机的简报天天报一个并不存在
# 的降级。
