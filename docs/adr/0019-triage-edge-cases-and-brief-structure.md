# 分拣的边界情形与简报结构

## Context

三条决策是在复核**不同轮次决策之间的交互**时发现的缺陷，而非独立设计问题。它们都属于分拣层的边界情形。

**其一：突发事件会掉进裂缝。** 新建门槛（ADR-0007）要求一条判断必须能接住未来的新闻，而允许弃权（ADR-0016）让接不住卡的信号被跳过。但一个重大而**一次性**的事件（大范围服务故障、关键人事变动、某个决定性的基准测试结果）可能既重要、又不可复用——它匹配不到任何卡，也不够格建新卡，于是被静默丢弃。系统会系统性地跳过读者最关心的那类事件。

**其二：冷却期与排序冲突。** 排序规则按「匹配度 × 热度」取第一名，而冷却期规定同一张卡三天内不得再成文。若排在第一的卡正在冷却，没有任何规则说明该顺位取第二名还是当日弃权。

**其三：简报结构未定。** 简报是唯一的观察入口与介入通道（含待处理成稿、退役/合并的否决、熔断告警、风格提议），且看守要靠它判断系统是否存活。结构不固定会使本人每天重建阅读路径，也使"简报是否完整"无法校验。

## Decision

**突发事件的去向**：不为它开例外（不建一次性卡），但将其列入简报的「**值得关注但无卡可接**」列表，供本人人工指定撰写。理由：为一次性事件写出的文章本质是新闻综述，而本系统的价值在观点；但不应让本人看不见系统的这个判断。

**冷却期优先于排序**：冷却中的卡本轮**不参与竞争**，直接顺位取下一名。若所有候选卡都在冷却，则当日弃权。理由：冷却期的目的是防重复，不是惩罚其他选题；有能力写却不写只是白白弃权。

**简报采用固定五段式**：

1. **今日结论** — 发了什么 / 弃权及原因（弃权必须区分"无选题"与"稿子审不过"）
2. **采集与分拣概览** — 含低置信度列表、无卡可接列表
3. **本篇文章与发布结果** — 含待处理成稿、已发布内容的可疑之处
4. **资产变动** — 新建卡、修订、退役与合并建议（等你否决）
5. **需你介入的事项** — 熔断、否决权、风格提议

## Consequences

- 突发事件的处置路径依赖**本人读简报**。若本人长期不看简报，这类事件会被永久丢弃——这是"只写有认知支撑的观点"这一立场的必然代价，不是缺陷。
- 冷却期优先于排序使系统在卡片库较小时**更容易弃权**：冷启动期只有 3–5 张卡，若它们都在冷却，产出会明显低于每日一篇。这是可接受的，且会随卡库增长自然缓解。
- 固定五段式使简报可被程序校验完整性，因而看守可以判断"简报存在但内容残缺"这一情形，而不只是"简报存在与否"。
- 五段式中的第 4、5 段承载了本设计里所有**需要人否决**的机制（退役、合并、风格提议、熔断）。这意味着简报不是报告，而是本系统真正的**人机接口**。
