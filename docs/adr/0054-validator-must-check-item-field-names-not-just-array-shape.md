# 校验器要校验数组项的字段名，不只是「它是数组」

## Context

2026-10-22 的分拣决策里，我把 `low_confidence_skipped` 写成了：

```json
[{"cluster": "个人变现与副业账本（…）", "confidence": 0.78, "reason": "素材最贴赛道，但…"}]
```

`triage.py --validate` 返回 `{"ok": true, "problems": []}`，退出码 0。

然后 `brief.py:366` 按 `it["event"]` 渲染标题、按 `it["why"]` 渲染原因——两个键都不存在，
`.get()` 返回空字符串。于是 `reports/2026-10-22.md` 的「低置信度（已跳过）」段变成：

```
- （0.78）
- （0.66）
- （0.55）
- （0.5）
- （0.12）
```

五条被跳过的簇，**簇名和跳过理由全部丢失**，只剩下五个小数。而简报的 ② 段本该是
「今天为什么没写这五件事」的唯一出口。

## 发现

### 一、校验器只检查了容器类型，没检查契约

原代码：

```python
for key in ("low_confidence_skipped", "no_card_available"):
    if key in raw and not isinstance(raw[key], list):
        extras.append(f"{key} 应为数组")
```

它防的是「写成对象而不是数组」。写成数组但项里字段名漂移，它一句话不说。
而 `SKILL.md:91-92` 明写了形状 `[{"event": "...", "confidence": 0.41, "why": "..."}]`
——契约是写下来的，只是没被执行。

### 二、这是 ADR-0042 的同型缺陷，不是新问题

ADR-0042 修的是 `parse_frontmatter` 有三份拷贝、`triage.py` 那份漂移导致
`covered_events` 列表项被静默丢弃。这次的形状完全一样：

- 字段名是**隐式契约**（没有 schema 文件，只有 SKILL.md 里的一段示例）
- 消费方用 `.get()` 读，读不到时**返回空字符串而不是报错**
- 上游生产方（我）凭记忆写 JSON，漂移的成本是零
- 结果是「安静地少显示一行」，退出码仍是 0

区别只在于：ADR-0042 是**解析器**漂移，这次是**生成器**漂移。同一根因的两端。

### 三、为什么 `ok: true` 比报错更危险

如果校验器直接拒绝，我当场就会改字段名，成本是十秒。它放行之后：

- 简报带着五个空条目提交入库（`d93d447`）
- 简报是人每天唯一读的东西，也是看守判活的依据（ADR-0038）
- 看守只校验 ①–⑤ 五个 marker 是否存在，**不校验段落内容非空**
- 所以这个缺陷可以一直存在，直到某天有人问「这五个数字是什么意思」

ADR-0040 记的是「每轮死在第 2 段且第 1 段产出永不落地」这类响亮的失败；
这一类是安静的那种。

## Decision

### 一、`validate_decision` 校验数组项的必填字段

`low_confidence_skipped` 与 `no_card_available` 的每一项都必须是对象，且
`event`、`why` 两个字段非空。缺任何一个都进 `problems`，`ok` 置 false。

报错文案带上**实际存在哪些键**（`现有键：['cluster', 'confidence', 'reason']`），
因为字段漂移时最需要的信息是「我到底写成了什么」，而不是「你少了一个字段」。

### 二、范围只到「简报会读到的字段」，不追求完整 schema

`confidence` 缺失只是少显示一个括号数字，简报仍然可读，因此不校验。
判据是：**缺了它，这一条在简报里是否还能被理解**。

这条判据让校验器保持在「结构性合法」的范围内，不去做语义判断——
语义正确性仍归人工复核（ADR-0019）。

### 三、不改简报的容错

`brief.py` 继续用 `.get()` + 空字符串兜底。理由：简报是最后一环，
它的职责是**尽力输出**而不是拦住运行；拦在分拣层，因为那里还来得及改。

如果反过来让简报抛异常，那么一个字段名错误会让整份简报消失，
连带看守误判系统死亡——代价比少显示一行大得多。

## Consequences

- 分拣决策的字段名漂移会在 `--validate` 阶段被拦住，代价从「简报静默缺内容」
  变成「重跑一次校验」。这是本项目第一次让**生成侧**的契约错误有出口。
- 校验器多了一条与简报耦合的规则：`brief.py` 若将来改读别的字段名，
  必须同步改 `triage.py` 的检查。**这是新增的耦合**，与 ADR-0042
  抽 `cardfm.py` 消除重复的方向相反——因为这里不是两份实现，
  而是「生产方要满足消费方」，只能靠显式检查。
- 新增失败模式：校验器现在会因为一个纯展示字段报错。若某天确实想让
  `low_confidence_skipped` 支持自由格式，需要先改这里，而不是绕过。
- 已发生的损失不可追回：`d93d447` 那次提交里的简报是坏的，
  已用同一份决策文件重跑 `brief.py --date 2026-10-22` 修正并重新提交。
  这也说明「简报可以重出」是个必要的性质——它是纯派生数据，不含独占信息。
- 遗留边界：`abstain_reason` 与 `decision` 内部的 `money_point`、
  `ranking_note` 等字段同样被简报消费，但本轮只校验了这两个列表。
  不做全量 schema 的理由见 Decision 二；若再出现一次同类丢失，应升级为
  一份显式的 `decision.schema.json` 而不是继续打补丁。

  > **勘误（ADR-0058 落码时实测）**：上面这句「同样被简报消费」是错的。
  > `money_point` 当时**没有任何消费者**——`brief.py`、`build_brief.py`、
  > 本阶段 SKILL.md 三处 `grep` 全部为 0 命中，唯一提到它的是本文件这一行。
  > 分拣从 2026-10-21 起每天写 300+ 字，写完就丢。所以这一条遗留边界的真实
  > 形状不是「字段没校验」，而是「字段连消费方都没有」；补校验之前必须先补
  > 消费方，否则校验只会让一个没人读的字段变得更严格。
  > ADR-0058 补上了两处消费（写作任务书 + 简报③段）与校验。原文保留不改，
  > 因为「当时的判断错了」本身是本仓库反复出现的缺陷形状之一。
