# ADR-0041：系统建卡的路径与 `action: new` 必须点名 `card_file`

## Context

2026-10-17 的无人值守运行里，分拣层第一次主动提出建卡建议：当日「AI 资本定价的重估」
一簇热度最高（头条 947098 / 943151），而当时 6 张卡无一接得住这一议题，于是它被列入
简报的 `no_card_available`，并写明「建议列为下一轮新建卡的首选」。用户据此要求建卡。

建卡过程中暴露两件事：一、**没有建卡脚本**，`knowledge/cards/` 由谁写、怎么写没有
实现路径；二、`validate_decision` 对 `action: new` **不校验 `card_file`**，而这正是
第 3 段写回取卡的唯一依据。

## 发现

### 一、建卡动作没有脚本，只有散文指引

`.agents/skills/newsagg-*/scripts/` 下没有任何脚本写 `knowledge/cards/`：`grep -rn
"knowledge/cards"` 只命中 `run_all.sh`（给 agent 的 handoff 散文）与 `writeback.py`
（只追加修订，不建卡）。而 ADR-0018 的所有权表把 `knowledge/cards/` 划给**系统**，
并写明「建卡、追加修订（受新建门槛与每日上限约束）」。

也就是说：**建卡这一步当前由 agent 读散文指引、手工写 markdown 完成**。这与
`writeback.py` 把「追加修订」做成确定性脚本的处理方式不一致——同一个目录，一半由
脚本写、一半由模型手写。

### 二、`action: new` 不要求 `card_file`，缺失时写回被静默跳过

`validate_decision` 原先对 `new` 只校验 `new_issue` 与 `reusable_because`。实测：

```
new + 完全没有 card_file → {'ok': True, 'problems': []}
new + 不存在的 card_file → {'ok': True, 'problems': []}
```

而第 3 段的写回是 `if [[ -n "$CARD" ]]` 才执行，`$CARD` 取自 `dec_field card_file`；
取不到就打印「（决策未给出 card_file，跳过写回）」——**不报错、不影响发布**。

后果与 ADR-0040 发现一的形态相同：**新卡永远不会拿到 `covered_events` 与
`last_written`**，认知资产停止生长，而整轮运行报成功。这正是 ADR-0007 说的
「发布后自动写回是越写越强的实际闭环点；没有它，系统只会重复劳动」被静默破坏。

两处缺陷叠加后的最坏路径是：分拣判 `new` → agent 忘了（或没能力）写卡 → 决策里
没有 `card_file` → 校验放行 → 发布成功 → 写回跳过 → **这张卡此后每轮都以空
`covered_events` 参与匹配**，防重复发文的关键字段永久失效。

## Decision

1. **建卡由 agent 执行，但必须留下可校验的痕迹。** 保留"没有建卡脚本"这一现状
   （建卡需要判断——议题命名、判断正文、边界与反方都是散文，与 ADR-0025「技能装
   判断」一致），但把它的**存在性**变成确定性校验：`action: new` 必须给出
   `card_file`，且该文件必须在 `knowledge/cards/` 下真实存在。校验器拒绝两者任一
   不成立的情况，附上失败后果。
2. **建卡与决策是同一个动作，不可分离。** 不允许"先出决策、稍后补卡"：卡片是分拣
   层的唯一读入，决策产出时它必须已经在位，否则下一轮的匹配就少了一张卡。
3. **`run_all.sh` 的 handoff 与 SKILL.md 同步写明这一点**（原文已有"并把文件名填进
   `decision.card_file`"，本 ADR 把 SKILL.md 的动作表与硬规则 3 补齐到同一要求）。
4. **本 ADR 不引入建卡脚本。** 若将来建卡频率上升（例如卡库需要批量治理），再考虑
   把**结构部分**（frontmatter 与五节骨架）脚本化、把判断部分留给模型——但那要先
   有证据表明手工建卡成为瓶颈。

## Consequences

- **"散文指引 + 确定性校验"是这对矛盾的正解。** 判断不能脚本化，但判断的**产物**
  必须被结构校验。ADR-0039 的 `kept_new`、ADR-0040 的 `git_pull` 与本 ADR 的
  `card_file` 是同一模式的三个实例：**只要某一步的输出是下一步的输入，它就必须被
  校验，而不能靠调用方记得**。
- **建卡仍未自动化，因此它是一次人工介入点。** 无人值守下 agent 必须自己完成建卡
  并写入正文——这依赖模型能力，是本系统里少数"正确性无法用确定性脚本判定"的环节
  （与残余风险 12「写作约束靠选题包携带」同类）。校验器只能保证卡**存在且结构合法**，
  不能保证判断**有质量**。
- **首张系统建的卡是 `ai-capital-pricing-shifts-to-unit-economics.md`**，其判断在
  建卡后即被自检修正：初稿断言「正在从能力叙事转向单位经济」，而卡自身的三条判据
  （投入端/回报端/资金端同时转向）在当日证据下**未同时成立**（判据 1 反向：微软、
  Meta 踩刹车）。修正为「正被要求给出单位经济（转向尚未确认）」。这条修正作为一条
  **未复核**修订写进卡中——理由：观点卡是分拣层唯一的读入，一句超出证据的判断会被
  下一轮直接当成事实复用。
- **空 `covered_events` 的卡有真实风险**：它以"从未写过"的姿态参与匹配，容易反复
  被选中（冷却期不生效，因为 `last_written` 为 null）。这一点在卡库变大后需要复核，
  本 ADR 仅记录。
